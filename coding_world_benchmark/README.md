# Coding World Benchmark

`coding_world_benchmark.py` creates controlled, isolated Python repositories for C2-style bug repair. Every trial edits a real source file and runs `unittest` for visible and hidden tests.

Run the benchmark from the repository root:

```powershell
python -m coding_world_benchmark.coding_world_benchmark
python -m pytest coding_world_benchmark
```

Conditions B--G compare a simple ReAct policy, the full closed-loop policy, and removal of failure memory, exploration, re-observation, or candidate suppression. The report records success, hidden/regression testing, repair iterations, file and test activity, failure recovery rate, and hypothesis efficiency.

The bundled policies are deterministic operationalizations of the experimental conditions, not LLMs. Use `save_external_result` to store Codex or same-model ON/OFF trial records in the same schema; do not interpret an absent external run as a Codex comparison.

`coding_dialogue.py` integrates `portable_japanese_dialogue` as a language interface. It turns Japanese instructions into inspectable coding goals, asks a clarification question for ambiguous deletion-history requirements, remembers change records for references such as "さっきの修正", and produces reports only from recorded execution results.

`autonomous_repair_experiment.py` adds the L1--L5 scaffolding experiment. Its L2 trials provide only Japanese task text, a repository path, and test execution: the transparent baseline scans source files, generates file-specific hypotheses and concrete edits, then validates them with `unittest`. The six hold-out domains are cache, inventory, parser, filesystem, scheduler, and session. This is evidence for observation-driven hypothesis generation within a deliberately narrow repair grammar, not evidence of general Codex-level repository understanding.

`heterogeneous_l3_experiment.py` is the L3 test. It holds the post-operation state contract constant while varying the implementation among dictionary, list, SQLite, JSON, dataclass, and cache-invalidation representations. It compares an observation-driven state-transition agent with an L2-only `get` to `pop` pattern baseline, and records hidden/regression pass rates, files read, irrelevant reads, generated/rejected hypotheses, attempted edits, and test runs.

`operation_discovery_l4_experiment.py` tests three contract types: removal, update visibility, and duplicate prevention. It derives candidate mutations from source and test observations, selects with real tests, and compares a rule baseline with closed-loop and recovery ablations. Its mutation grammar remains finite and explicit, so it measures operation discovery within that grammar rather than unrestricted repair invention; failure atomicity and transaction rollback remain hold-out contract types for a later expansion.

`l45_holdout_experiment.py` is an adversarial grammar-boundary test. Its independent seeded generator creates 100 repositories spanning transaction rollback, cache/persistent coherence, idempotency, and resource cleanup. The current L4 candidate generator receives only the repository and tests. A result of zero coverage and zero repair success is the expected falsification result: these contracts require operations outside the current finite grammar and must not be presented as L4 generalization.

`operator_invention_l46_experiment.py` tests L4.6 operator composition. A primitive composer derives `SAVE_STATE -> TRY -> RESTORE_STATE -> RAISE` from an observed mutation followed by a failure, records the successful composition as `ROLLBACK`, and reuses it in a hold-out repository with different state and parameter names. It compares acquisition and reuse costs against a no-operator baseline. This is one compositional operator family, not unrestricted operator invention.

`compositional_operator_l47_experiment.py` is the L4.7 compositional-search test. One composer receives a general primitive vocabulary -- `OPERATION`, `EFFECT`, `RESULT`, `TRY`, `EXCEPT`, `FINALLY`, `END`, `GUARD`, `REPEAT`, `RAISE`, `SAVE`, `RESTORE`, `READ`, `WRITE`, `REMOVE` plus the deliberately useless `LOG`, `SLEEP`, and `TOUCH` -- and no repair rule for any contract family. For each of four unseen contracts (transaction rollback, cache/persistent coherence, guaranteed resource cleanup, idempotency) it searches compositions of those primitives under a bounded grammar, selects only with real contract tests, compresses the successful trace into an operator whose arguments are stored as observation roles rather than concrete names, and reuses it. `search_is_family_agnostic` re-checks mechanically that no search, abstraction, or reuse function mentions a family name; operator labels such as `ROLLBACK` are attached post hoc from the discovered primitive signature and never steer the search.

The report records, per family, the discovered signature, search trials, the first rejected candidates, hold-out reuse cost, MDL gain, and re-verification of the accepted program by a real `unittest` process. It ablates compression with four conditions on the same eight hold-outs: `full`, `parameterized_operator`, `memorize_exact` (replay the first successful trace verbatim), and `no_compression` (search from primitives every time). A structural hold-out re-tests the rollback operator on a three-file repository whose state is an object attribute mutated through a helper. The composition grammar forbids repeating an identical primitive instance in one program, bounds program length, and bounds loop iterations, so this measures composition search inside a bounded general grammar, not unrestricted program synthesis.

`scientific_diagnosis_l48_experiment.py` adds the first scientific-agent control on top of the coding benchmark. It writes real miniature repositories and runs `unittest`, but the measured capability is the critic after execution: it separates implementation failure, instrument failure, low statistical power, confounding, negative results, and positive results. This tests the design requirement that a failed experiment must not automatically become another code-patching attempt. A naive success-only coding policy is included as the contrast condition.

`knowledge_gap_l49_experiment.py` tests the next control layer: whether a diagnosis can produce explicit `KnowledgeGap` objects and choose retrieval only when the unknown is decision-relevant. It uses a deterministic retrieval fixture rather than live web search, so the measured capability is gap precision/recall, unnecessary-search suppression, blocking-gap resolution, and post-retrieval action accuracy across `no_retrieval`, `always_search`, `keyword_search`, and `knowledge_gap_driven` policies.

`evidence_grounded_l50_experiment.py` is a sealed retrieval benchmark for the first L5 step. It does not use live Web access; instead it gives the retriever an adversarial fixed corpus with agreeing authoritative sources, misleading top snippets, conflicting sources, unresolved gaps, and irrelevant true sources. The measured capability is whether retrieved pages become attributed `GroundedEvidence` with relevance, authority, independence, uncertainty, and quoted spans, while keeping unsupported claims at zero for the evidence-grounded policy.

`experiment_revision_l51_experiment.py` tests whether grounded evidence improves experiment plans without becoming a shortcut to conclusions. It converts supported evidence into attributed `RevisionProposal` objects, routes implementation failures to code repair, abandons decisively negative hypotheses, and holds revision when evidence is conflicting or unresolved. The comparison covers `no_revision`, `diagnosis_only_revision`, `retrieval_without_grounding`, and `evidence_grounded_revision`, with harmful and unnecessary revisions measured explicitly.

`autonomous_loop_l52_experiment.py` connects L4.8--L5.1 into a sealed autonomous scientific loop. It tracks `ScientificLoopState` with diagnosis, gap, evidence, revision, execution, and budget histories, then evaluates end-to-end scientific outcomes rather than component accuracy. The task set includes direct positive and negative exits, sample-size/measurement/control revisions, code repair routing, conflicting and unresolved evidence holds, a second-revision case, and a cyclic low-power case that must stop on budget.

`live_web_retrieval_l53_experiment.py` exposes retrieval to deterministic live-Web disturbances: timeout, HTTP/browser failure, missing source, stale source, source conflict, parse failure, insufficient evidence, and success. It compares sealed grounded retrieval with top-1, search-only, grounded, and grounded-with-fallback policies. Stale, irrelevant, malformed, conflicting, or absent content becomes unresolved/conflicting evidence instead of an unsupported claim; fallback recovery and post-retrieval action are measured separately. The fixture is sealed and reproducible, while a real connector can later map its failures to the same `LiveRetrievalStatus` values.

`live_retrieval_adapter_l531_experiment.py` adds the L5.3.1 transport boundary. Injected HTTP and browser adapters map status codes, exceptions, redirects, content types, gated/empty HTML, stale pages, and irrelevant content into `LiveRetrievalStatus`. HTTP 200 is not treated as evidence success automatically. The record/replay transport makes raw responses replayable for parser and status-mapping tests, and browser fallback recovery is measured independently.

`query_refinement_l532_experiment.py` adds the L5.3.2 search-decision layer. It generates category-specific queries from `KnowledgeGap`, refines only when the result set lacks a sufficiently relevant and authoritative source, ranks by relevance, authority, freshness, and source independence, and canonicalizes URLs to remove tracking-parameter duplicates. The sealed fixture measures query generation, refinement success, top-1 ranking, duplicate reduction, and query-budget violations before connecting to a live search engine.

`citation_grounding_l533_experiment.py` adds the L5.3.3 evidence lineage layer. Ranked sources are fetched through the L5.3.1 HTTP/Browser adapters, converted into citation nodes, deduplicated before fetching, and fused only when independent claims agree. Conflicting claims remain unresolved as conflict, stale pages contribute no citation, and browser-only content follows the same grounding path. The sealed cases measure citation completeness, source integration, duplicate-fetch suppression, browser fallback, and unsupported-claim rate.

`external_llm_reviewer_l54_experiment.py` adds the L5.4 external-review layer. The reviewer emits `ReviewProposal` objects for missing evidence, counterhypotheses, alternative explanations, search queries, and methodological risks; primary-source verification is required before creating a `VerifiedReview`. The comparison includes evidence-only, always-review, direct-trust, and workspace-selected policies. Direct trust is a negative control for hallucinated reviews, while the selected policy suppresses unnecessary calls and holds contradicted or unverified proposals.

`open_world_l55_experiment.py` adds the L5.5 end-to-end task boundary. Only natural-language research prompts are exposed to the runner; it derives an initial hypothesis and plan, then composes the L5.2 diagnosis/retrieval/revision loop with safe abandon and unresolved holds. The sealed task set measures scientific outcome, route completion, unsupported final claims, budget violations, and execution cost across coding-only, diagnosis-only, retrieval/revision, and full-loop policies. It is an open-world-style interface with deterministic tasks, not a claim of unrestricted scientific generality.

`real_environment_l56_experiment.py` adds the L5.6 real-boundary harness. `RealRepositoryAdapter` inspects a caller-provided repository and runs its actual test command; `LiveHttpSearchAdapter` fetches actual HTTP URLs and reuses the L5.3.1 normalization boundary; and an external reviewer is an explicit callable interface. The integration result requires repository tests, successful content extraction, and the requested reviewer call, so HTTP 404 or unusable content cannot become a successful scientific run. Tests use a local HTTP server and temporary real repositories for deterministic verification.

`real_external_llm_reviewer_l57_experiment.py` adds the L5.7 reviewer provider boundary. `ChatGPTWebReviewer` is attempted first; on connection failure, `OpenAIAPIReviewer` loads `OPENAI_API_KEY` or `CHATGPT_API_KEY` from `.config` and calls the Responses endpoint. Both providers return structured `ReviewProposal` objects only, with classified failures, latency, and secret-free results. The API fallback is tested against a local HTTP server, while production callers can inject a real ChatGPT browser transport.

`open_world_real_l58_experiment.py` adds the L5.8 real-task boundary. A caller supplies only a natural-language research prompt, repository path, evidence URL, and required terms; the runner inspects the repository, runs its real tests, retrieves HTTP evidence, routes Web ChatGPT to the API fallback configured by `coding_world_benchmark/.config`, and produces a safe supported/unresolved report. Human interventions and unsupported final claims are recorded explicitly. Tests use temporary repositories and local HTTP endpoints; real external calls occur only when a caller supplies the real Web/API router.

`coding_agent_app.py` provides the local desktop coding-agent UI. It lets the user choose a workspace folder, send conversational work instructions, inspect files, search the workspace, run `unittest`, and view results in a transcript. Natural-language requests are handled by local repository analysis only: structured reports, grounded explanations, and compact search summaries do not call an LLM API or read API credentials. Start it with `python -m coding_world_benchmark.coding_agent_app`.

`repository_semantic_l58_experiment.py` adds repository semantic understanding. It builds an AST-backed symbol index, local call graph, simple assignment/return provenance, and line-grounded `CodeEvidence`; `context_for` returns competing interpretations when a phrase such as `initial state` matches multiple experiment entry points. This is a conservative static-analysis layer and does not claim full Python semantics.

`grounded_repository_explanation_l59_experiment.py` converts that local context graph into grounded natural-language explanations. Each `ExplanationClaim` carries `file:line:symbol` evidence, confidence, and an inference type (`direct`, `call_graph_inference`, `dataflow_inference`, `ambiguous`, or `runtime_unverified`). Explanation requests in the desktop app use this path directly, returning candidate symbols, static call/dataflow relations, and explicit runtime-verification limits instead of an unstructured keyword listing.

`formula_extraction_l60_experiment.py` adds the first mathematical semantic layer. It extracts Python assignment expressions plus Markdown/TeX formula blocks into `FormulaNode` objects, preserves source file/line evidence, normalizes Python expressions with SymPy, and emits LaTeX and referenced symbols. This is an extraction and representation benchmark; symbolic equivalence, derivation provenance, and runtime value mapping remain later L6 stages.

`math_spec_to_code_l61_experiment.py` adds a bounded mathematical-specification-to-code path. It parses a natural-language first-order ODE specification into `SpecificationIR`, selects RK4 or Euler, generates a Python AST/source artifact, and checks the generated RHS against the original symbolic expression at numeric sample points. The current scope is intentionally one state and one equation; multi-state systems, invariants, and broader algorithm selection are later extensions.

`structured_repository_report_l62_experiment.py` adds request classification and compact causal repository reports. File-targeted summarize/explain requests resolve the target module and render its role, key symbols, experiments, call paths, dataflow, and line evidence. The desktop app uses this report for file-targeted local investigation instead of a raw keyword listing.

`canonical_ir_l63_experiment.py` adds the mixed-language canonicalization layer for coding requests. Japanese, English, and mixed requests are normalized into an English `CanonicalTask` with canonical concepts such as `INITIAL_STATE`, English relation enums such as `flows_to` and `verified_by`, and inferred task edges. Structured repository reports now include this inspectable internal IR while keeping the user-facing report in Japanese.

`language_understanding_l64_experiment.py` adds a machine-graded language-understanding benchmark above the canonical IR. It scores intent, target resolution, reference resolution, ambiguity detection, repository-context need, execution/modification flags, operation-sequence extraction, and Japanese/English consistency separately. The included ablation compares a keyword parser with canonical IR plus context, so language improvements can be tested before connecting them to coding or scientific task success.

`execution_router_l65_experiment.py` adds the execution action route for local coding-agent requests. Requests such as "シミュレーションのpythonファイルを実行して" are classified as execution, README command snippets and Python files become `ExecutionCandidate` evidence, a validated `ExecutionPlan` is built, and `subprocess.run` captures return code, stdout/stderr, elapsed time, and generated files. Search results are no longer the terminal answer for execute requests; they are evidence used to choose and run a command.

`experiment_semantic_l66_experiment.py` adds experiment-specific semantic extraction for local investigation requests such as "pythonでのシミュレーションがどのような設定で行われているか調査して". Candidate experiment files are resolved from README commands or Python filenames, then AST analysis extracts CLI parameters, constants, initial conditions, compressed execution logic, observables, outputs, success conditions, and line evidence into an `ExperimentSpec`. The desktop app now returns an experiment configuration report instead of stopping at a file list for these requests.

`math_algorithm_l67_experiment.py` adds the mathematical semantic route for requests such as "pythonシミュレーションのアルゴリズムを数式で表して". Local AST analysis resolves the experiment entry point, classifies parameters, state updates, physical equations, observables, and initial conditions into `MathematicalModel`, and renders evidence-backed LaTeX blocks. The app keeps repository search as target-resolution evidence and returns a mathematical algorithm report instead of a search listing.

The L6.8 extension adds `EquationIR` reconstruction for governing equations. Euler-like code updates such as `x = x + v * dt` and `v += a * dt` remain available as confirmed discrete equations while also producing explicitly marked continuous-limit inferences such as `dx/dt = v` and `dv/dt = a`, with source evidence and confidence. Non-Euler expressions are not promoted to continuous equations without a matching update pattern.

`scientific_experiment_l68_experiment.py` adds a design-and-verify fallback for natural-language physics requests with no repository target. The bounded special-relativity benchmark turns the train-and-garage question into hypotheses, assumptions, Lorentz equations, an analytic strategy plus numerical parameter sweep, generated Python source, subprocess execution, and a conclusion. Repository search is no longer a terminal failure for this supported domain.

`open_research_l69_experiment.py` adds the general open-question layer using `ResearchQuestionIR`, `KnowledgeGap`, explicit controls, measurable predictions, strategy selection, generated code, execution, and diagnosis. The accelerated charged-particle radiation request is a hold-out-style local benchmark: it parses electrodynamics intent, resolves a bounded Lienard-equation knowledge gap, tests zero-acceleration and beta sweeps, and reports the limitation that this is an analytic radiation-law evaluation rather than a full electromagnetic-field solver.

`scientific_knowledge_l70_experiment.py` adds the intent-routed scientific knowledge layer. Literature requests become `SCIENTIFIC_RESEARCH` and are converted into paper-backed `ScientificEvidence` plus `ResearchPlan` claims, assumptions, equations, unresolved points, and proposed experiments. Wave-equation requests become `MATH_DERIVATION` and use an assumption-bounded separation-of-variables derivation with LaTeX output instead of repository search. The initial paper registry is offline and inspectable; it can be replaced by the existing live retrieval adapter without changing the IR.

`knowledge_retrieval_l71_experiment.py` adds the seven-part knowledge loop: `KnowledgeGapDetector`, `QueryGenerator`, injectable `SearchAdapter`, injectable `PageFetcher`, `EvidenceExtractor`, `SourceRanker`, and `KnowledgeStore`. The scientific research route now exposes canonical English queries, source relevance/authority/confidence, supported versus unresolved status, and evidence URLs before integrating knowledge into the research plan. The default adapter is deterministic offline replay; live web and paper adapters can be injected at the boundary.

`live_scientific_adapters_l72_experiment.py` provides the live boundary implementations. `HttpSearchAdapter` queries DuckDuckGo HTML and normalizes result links/snippets into `SearchResult`; `HttpPageFetcher` retrieves HTML with `urllib`, removes scripts/styles, and returns bounded visible text. Set `CODING_AGENT_LIVE_WEB=true` before starting the agent to inject these adapters into `ScientificRetriever`; when unset, deterministic offline replay remains active.

`conversation_memory_l73_experiment.py` adds compressed reusable knowledge memory. Important equations, sources, confidence lines, conclusions, and decisions are deduplicated into `.knowledge_memory.json.gz` at application shutdown and after each completed interaction. On the next interaction, related facts are recalled and appended as `【再利用された知識】`; repeated facts increase their use count instead of being duplicated.

`open_scientific_compiler_l74_experiment.py` adds the ResearchPlan-to-ExperimentPlan compiler for pairwise distance from mutual information or entanglement entropy. It compares multiple candidate mappings, includes shuffled/uncorrelated controls, generates and executes Python, and reports reconstruction error and triangle-inequality violations. The result is explicitly a finite synthetic-model comparison, not a universal distance formula.

`workspace_operations_l75_experiment.py` adds the explicit workspace action layer. Delete requests are routed to `DELETE_DIRECTORY`, resolved against the workspace with traversal protection, rejected when ambiguous, moved reversibly into `.agent_trash`, and verified after the move. Search is used only to resolve the target; it is no longer the terminal answer for explicit delete commands.

`validation_memory_l76_experiment.py` adds validation knowledge compression. Validation/test/benchmark files are reduced into concept-level `ValidationKnowledge` records with procedures, success conditions, failure modes, fixes, reusable operators, and L1 file/line provenance. Records are merged by concept into a compressed JSONL store and retrieved for later validation requests, so the agent reuses patterns such as gauge-theory validation, conservation audits, finite-size scaling, and counterexample search.

`local_paper_l77_experiment.py` adds local paper ingestion. PDFs are classified from their extracted text layer as `TEXT_PDF` or `SCANNED_PDF`; scanned pages are rendered through Poppler and passed to an injectable OCR backend. The resulting `PaperKnowledge` keeps page provenance for sections, LaTeX equation evidence, figure captions, unresolved pages, and extraction warnings. Requests such as "このフォルダのPDF論文を読んで知識化して" now use this route before repository search.

`paper_knowledge_quality_l78_experiment.py` adds OCR quality control and L7.9 evidence integration. OCR text is normalized conservatively, equations are checked for balanced delimiters and symbol/context consistency, and recovery, equation, symbol, structure, caption, provenance, and unresolved-page metrics are reported. `paper_to_scientific_evidence` promotes only page-grounded equations into the shared `ScientificEvidence` IR, while `compare_paper_knowledge` measures semantic equivalence between text-PDF and scanned-PDF results. The app now displays both the quality report and integrated evidence for local-paper requests.

The workspace action extension adds `MOVE_DIRECTORIES` with current-request priority over validation memory. Requests to combine SU2/SU3 validation folders resolve candidates from the filesystem, create a requested or default destination such as `su2_su3`, move the directories, verify source removal and destination existence, and report the operation. Ambiguous targets fail before creating the destination.

The move resolver now canonicalizes repeated SU2/SU3 concepts, supports `all_matching` target groups for requests such as "まとめて移動", accepts an explicit new-folder name such as `su2_su3`, and reports `0/n`, partial, or complete outcomes consistently. Memory can only strengthen filesystem candidates; it is not rendered as the operation result.

The web UI now stores threads per workspace in `conscious-agent-workspace-threads`. Switching a workspace loads that workspace's active thread and messages; creating a thread keeps multiple independent conversations under the same workspace. The previous single `conscious-agent-session` is migrated into a workspace thread on first load.

`algorithm_summary_l80_experiment.py` adds structure-based algorithm summaries. Requests such as `consciousness_modelのアルゴリズムを要約して` resolve the target module, rank its central functions, compress calls into process stages, extract state/data flow, and render line-level evidence. This route runs before generic validation-memory and repository-summary fallbacks, so search matches are not returned as the final answer.

`external_repair_l81_experiment.py` adds the external-review repair boundary. ChatGPT-style proposals are parsed into `RepairInstruction`, resolved against the actual repository graph, classified as invalid/partial/applicable, and passed through injectable `PatchExecutor` and `RegressionVerifier` interfaces. Without an explicit patch payload, the default executor generates a grounded `RepairPlan` but does not edit files or claim tests passed.

`autonomous_patch_l82_experiment.py` adds guarded patch synthesis. The deterministic first synthesizer handles explicit small edits such as `add function`, validates Python syntax, stages the candidate in a temporary workspace, runs regression tests there, and promotes only passing changes. Unsupported semantic proposals remain unmodified and are reported as `synthesis_unavailable`; arbitrary external text never becomes an unreviewed repository rewrite.

`semantic_repair_l83_experiment.py` adds dependency-ordered `RepairStep` decomposition. External proposals are detected before experiment/scientific routes using `IntentEvidence`; structured L8.3/L8.4 proposals become an acyclic repair DAG, while conversation memory is filtered by intent and is no longer appended to workspace-action or external-repair responses.

`autonomous_repair_l84_experiment.py` adds bounded repair retries. Failed temporary patches are classified as syntax, import, behavioral, expectation, target, or synthesis failures; a pluggable `RepairStrategy` may propose the next instruction, while repeated target/change/failure signatures stop the loop. Each retry remains isolated until its regression tests pass.

`semantic_change_compiler_l85_experiment.py` adds the Semantic-to-Code Change Compiler, the layer that was missing between L8.3 and L8.2. Proposal sentences are parsed into `SemanticRequirement` (verb, artifact identifier, anchor, members), grounded against the real `RepositoryGraph`, and lowered into `CodeChangeIR(file, symbol, operation, anchor, behavior)` over a fixed operation vocabulary: `ADD_DATACLASS`, `ADD_CLASS`, `ADD_FUNCTION`, `ADD_METHOD`, `MODIFY_ENUM`, `INSERT_ROUTE`, `REPLACE_BRANCH`, `ADD_TEST`, `ADD_IMPORT`. `SemanticPatchSynthesizer` renders that IR into `PatchCandidate` diffs, so semantic proposals such as `既存Routerの前にSemantic Parserを配置` are now editable instead of stopping at `synthesis_unavailable`. Generated routes are behaviour-preserving seams (a hook returning `None`) rather than invented logic, new modules and generated regression guards are created as real files, and any requirement whose identifier or anchor cannot be grounded stays `unresolved` with a stated reason instead of becoming a fabricated patch. `RepairStep` now carries `target_files`, `target_symbols`, `operation_type`, `expected_behavior` and `test_requirements`, and the L8.4 loop reports the grounding failure reason alongside `SYNTHESIS_UNAVAILABLE`.

`self_modification_l86_experiment.py` adds the self-modification benchmark. Nine fault fixtures rebuild the *shape* of faults this agent actually shipped -- six unwired capabilities (summarize, execute, move, research, derivation, external-repair routing), one missing type (`synthesis_unavailable`), one memory policy that is computed but never applied, and one out-of-scope fault whose fix lives inside a function body -- plus one healthy control. Each fixture runs detect (behavioural probe) -> diagnose (repository evidence only) -> generated `RepairInstruction` -> L8.3 decomposition -> L8.5 `CodeChangeIR` -> L8.2 patch -> L8.4 retry -> regression, with no human in the loop. `diagnose_workspace` receives a directory and probe output, never the fixture identity or its expected fault. Metrics cover `fault_detection_rate`, `diagnosis_accuracy`, `repair_grounding_rate`, `semantic_compile_rate`, `patch_success_rate`, `mean_attempts_to_recovery`, `regression_introduction_rate`, `unnecessary_edit_rate`, `human_intervention_rate`, `full_recovery_rate` and `false_repair_count`. The out-of-scope fixture and the healthy control are scored deliberately: a run that repairs either of them is wrong, so refusal is measured rather than assumed. Fixtures and diagnosis heuristics were designed together, so a high score is evidence that the loop closes on known fault shapes, not that it generalizes to unseen ones. Per-environment results are recorded in `TEST_MATRIX.md`; an environment-dependent failure is never counted as a pass.

`holdout_faults_l861_experiment.py` measures what L8.6 cannot: generalization. Six hold-out faults break the same capability categories in different ways -- a subprocess result computed and dropped, an inverted verification, an argument omitted at a call site, a skipped filter, a missing abstraction step, a skipped regression run -- and each is generated by corrupting a module that is known to pass, so every fixture has a known-good oracle and the break is an auditable `(before, after)` pair. The diagnoser was frozen before these fixtures were written and is not tuned against them. Cold result: detection transfers intact (`fault_detection_rate` 1.0 on unseen faults, because detection is a probe run rather than a pattern match) while repair does not (`repair_success_rate` 1.0 known vs 0.0 hold-out, `generalization_gap` 1.0). Three hold-outs were correctly reported as having no applicable detector; three were misdiagnosed by the generic unwired-capability rule and rejected by the regression gate, leaving no edits and no false repairs. L8.6 metrics are reported in two groups so these read correctly: repair coverage ("how far can it get alone") and decision accuracy ("does it repair when it should and keep its hands off when it should not"), with abstention on an unsupported fault lowering coverage while scoring as a correct decision. Diagnosis now ranks `DiagnosisCandidate`s by specificity before confidence, so narrow evidence ("this entry argument is never read") outranks generic evidence ("some function is not wired").

`behavior_monitor_l87_experiment.py` audits what the agent did against what the intent required. The existing L6.2 `RequestType` becomes an `ExpectedBehavior` -- required events, prohibited events, named postconditions and metric bounds -- written from what the request means for the person asking, not from what the implementation happens to do. The run is observed through the standard-library calls any implementation must make (`subprocess.run`, `shutil.move`, `Path.mkdir`, `Path.write_text`, repository indexing) plus a before/after snapshot of the workspace, so an answer that claims a move without moving anything fails the audit even though no exception was raised. `ExpectedBehavior` is data: postconditions and metric bounds resolve through registries, so a contract can be written down and reviewed instead of hiding inside an assertion. Captured defaults such as `runner=subprocess.run` are rebound too, otherwise a subprocess that did happen would be reported as missing. On its first run against the shipped agent the audit found a live bug: `is_move_directories_request` tested `\bSU[0-9]+\b`, and a Japanese particle is a word character, so `SU2とSU3の検証フォルダをまとめて移動して` never matched and move requests fell through to the validation-memory route without moving anything -- the F3 symptom still present in real code. `workspace_operations_l75_experiment.py` now brackets the ASCII class explicitly and the audit passes. Run it with `python -m coding_world_benchmark.behavior_monitor_l87_experiment [workspace]`.

`scientific_simulation_l88_experiment.py` routes natural-language creation requests for small scientific simulations into artifact generation rather than repository search. The first supported domain is non-relativistic charged-particle motion in a uniform magnetic field. A request such as `一様磁場中で荷電粒子が運動するシミュレーションを作成して` becomes `IMPLEMENT_SCIENTIFIC_SIMULATION`, writes `charged_particle_uniform_B.py` and `test_charged_particle_uniform_B.py`, and reports the Lorentz-force equations. If the request also says to execute, the generated unittest suite is run and the return code is reported. Conversation memory uses `scientific_modeling_only` for this route, excluding SU2/SU3 gauge or router-repair memories from the final answer.

`goal_semantics_l89_experiment.py` adds the Goal/Action Semantics layer above individual routers. Natural language is first mapped to a `GoalIR` containing operators such as `KNOW`, `CREATE`, `CHANGE`, `EXECUTE`, `VERIFY`, the desired final state, desired properties, completion conditions, and prohibited early exits. `compile_task_graph` turns that into required actions, and `contract_from_goal` states observable requirements such as `FILE_WRITTEN >= 1` or `SUBPROCESS_STARTED >= 1`. This makes search a tool rather than a valid final state for CREATE/CHANGE/EXECUTE/VERIFY goals. `process_execution.py` is the one way this repository starts a child process. `subprocess.run(..., text=True)` decodes the child's pipes with the *locale* codec; on a Japanese Windows install that is cp932 while the output is UTF-8, so one unmappable byte raises `UnicodeDecodeError` inside the reader thread, `communicate()` hands back `stdout=None`, and the caller dies on `None + str`. A UTF-8 container cannot reproduce it -- the first real Windows run turned up 31 failures from this single cause, including the shipped agent's `/tests` and EXECUTE routes. `run_text` fixes it at the root: UTF-8 in both directions (`PYTHONIOENCODING`/`PYTHONUTF8` for the child, explicit `encoding` with `errors="replace"` for the parent), `stdout`/`stderr` guaranteed to be `str`, and `sys.executable` substituted for a bare `python`, which on Windows is often the Store alias stub that does not start (on this machine only `py -3` worked). `test_process_execution.py` reproduces the failure shape on any platform by having a child emit unmappable bytes, so the regression is guarded without needing a cp932 locale.

`goal_execution_loop_l812_experiment.py` turns the L8.11 plan into a loop. L8.9 judges one finished response and stops there, so a run that answered `作成して` with a file listing reported `GOAL_NOT_ACHIEVED` and ended. L8.12 reads each unmet observation off that same contract, translates it into a remediation directive from a closed vocabulary (`WRITE_ARTIFACT`, `APPLY_WORKSPACE_CHANGE`, `RUN_COMMAND`, `CAPTURE_RETURN_CODE`, `REPORT_VERIFICATION`, `ADVANCE_BEYOND_SEARCH`) and calls the executor again carrying those directives. A gap the vocabulary cannot name escalates as `ESCALATED_UNSUPPORTED_GAP` instead of being guessed at, which is the same abstention rule L8.5 and L8.6 use. The termination rules are what make the numbers mean anything: a gap that survives its own remediation ends the run as `ESCALATED_NO_PROGRESS` rather than spinning to the budget, and that is kept distinct from `ESCALATED_BUDGET_EXHAUSTED`, which only happens when every round did change the gap. The fixtures are built around those controls -- an executor that reads directives recovers in two iterations, a deaf one that ignores them escalates in two, a goal already satisfied on the first attempt must finish in one iteration with no remediation round, and an information goal must not be pushed into writing a file.

`episodic_memory_l813_experiment.py` gives that loop a boundary. L7.3 already compresses a conversation into reusable facts, but it keeps one flat pool keyed by topic, so the only way it can separate two pieces of work is by guessing from words -- which is why its `recall` carries hand-written policy blacklists that drop every fact mentioning `gauge`/`su2`/`quantum` when the current task is a repair. L8.13 records the boundary instead of inferring it. An `Episode` is one finished unit of work distilled from the L8.12 `LoopOutcome`, and it stores the *keys* of the facts that work produced rather than the facts themselves, so L7.3 remains the one store and its `.knowledge_memory.json.gz` is neither rewritten nor reformatted. Recall then follows the boundary: a request continuing earlier work restores exactly that episode's facts, and a request starting new work gets nothing from earlier episodes at all, with no per-topic blacklist needed to achieve it. Resolution refuses to guess in the two cases where guessing is what corrupts a long conversation -- a name matching several episodes, and a name matching none -- because silently substituting the most recent episode for a name the user actually typed is the failure the layer exists to prevent. Names are narrow on purpose: a filename or a latin token carrying a digit (`su2`, `rk4`) identifies an episode, an ordinary noun never does, since a word every task uses would otherwise capture whichever episode happened to contain it. The probe set measures `reference_resolution_accuracy`, `wrong_episode_reuse_rate` and `stale_intent_leak_rate` against the controls that make them mean something: `clarification_accuracy` for the cases that must ask, and `unnecessary_clarification_rate` for the cases that must not, since always asking would drive wrong reuse to zero on its own.

`context_isolation_l814_experiment.py` measures whether L8.13 survives a long session, with L8.13 frozen -- neither the resolver nor `_REFERENCE_STOPWORDS` is touched, because a benchmark tuned until it passes measures the tuning. The protocol follows L8.6.1: the generator holds the ground truth and the resolver is handed the query string only, and a phrase probe is emitted only when the generator can show against the finished corpus that the phrase belongs to exactly one episode. Episodes are synthesised from component phrases (`古典一次元` + `イジング` + `相転移`), so components are reused as the corpus grows while the full phrase still names one episode to a reader. Across N = 2, 5, 10, 20, 50, 100 the result splits cleanly by reference kind: filenames, id-like tokens and bare recency stay at 1.00 accuracy at every size, while component phrases fall 1.00 -> 0.60 (N=5) -> 0.00 (N>=10), giving D(100) = 0.25 over the mixed probe set. Isolation itself does not degrade -- `stale_intent_leak_rate` and `new_task_contamination_rate` are 0.00 at every size. The important part is *how* the phrase probes fail: `wrong_episode_reuse_rate` is 0.00 throughout and every failure is a clarification request, so the resolver never silently substitutes one episode for another; it stops being able to rank candidates and asks. Token matching therefore does not scale past roughly ten episodes for compositional names, but it fails safe, which is what makes it shippable while the resolver is redesigned as a scoring problem.

`structural_resolver_l815_experiment.py` replaces the discrimination step L8.14 found wanting, and only that step. Whether a request is a reference at all stays a structural gate, and a reference carrying no content tokens still means the latest episode, because those were the parts L8.14 showed were working; what changes is that candidates are now scored, `S(e,q) = 3.0·A + 2.0·T + 0.2·G + 0.15·R - 4.0·C`, with coverage `T` the share of the query's content tokens an episode accounts for. An episode matching three components of a phrase outranks two that match one, which is what the old set-intersection resolver could not express. The top candidate is not simply taken: `CONTINUE` needs `S1 >= 0.8` and `S1 - S2 >= 0.4`, otherwise the answer stays `CLARIFY`. The weights carry one constraint that is asserted rather than tuned -- goal agreement and recency are circumstantial, so their combined spread is held below the margin and neither can license a `CONTINUE` on its own; only an artifact hit or token coverage can. That is what keeps 「SU2の検証を続けて」 a clarification when two SU2 episodes differ only by dimension, while 「3次元SU2の方を続けて」 and 「二次元SU2の方を続けて」 each resolve to their own episode rather than to whichever ran last. On L8.14 this takes phrase accuracy from 0.00 back to 1.00 at every size with `wrong_episode_reuse_rate`, `stale_intent_leak_rate` and `new_task_contamination_rate` all still 0.00, and `unnecessary_clarification_rate` down from 0.20 to 0.00.

Those numbers are tuning, not evidence, because the weights were chosen against L8.14. `holdout_resolution_l8151_experiment.py` is the cold measurement, with the resolver frozen and the vocabulary, the phrasings and the reference relations all new. Named references generalise cleanly: phrase references in unseen signal-processing vocabulary score 1.00, as do artifact, unknown-name and genuinely ambiguous probes, and overall accuracy rises 0.171 -> 0.457 over L8.13 while unnecessary clarification falls 0.366 -> 0.146. Isolation generalises too -- leak and contamination stay 0.00. The hold-out also overturns something L8.14 appeared to establish. `wrong_episode_reuse_rate` is 0.239, not 0.00: the safe-failure property was a property of L8.14's query distribution, not of the resolver. Temporal and relational references break it in one specific way -- 「その前の実験を続けて」 has its relation word consumed as a plain continuation marker, falls through to the bare-reference rule and returns the *latest* episode, and 「Xの後にやった方を続けて」 returns X itself. Both are off-by-one, and both answer confidently instead of asking. That is left unfixed on purpose, since repairing a defect found on a cold hold-out would turn the hold-out into development data; it is asserted in the tests so it cannot be lost, and it is what makes an episode relation graph a safety requirement rather than a convenience.

`layered_memory_l816_experiment.py` asks which parts of a long conversation survive compression and which have to be kept as original text, and it can be measured without a model because the compression here is real. L7.3's `_compact_lines` keeps only lines carrying a marker such as 結論 or 判定, so a turn reporting `格子サイズは 64x64、乱数種は 20260917 を使用しました。` alongside its conclusion reaches the long-term state as the conclusion alone -- the parameters are not stored anywhere afterwards, so no amount of searching the state can ground 「そのままの値を出して」. Four configurations are compared over one conversation: a short window of recent turns, the compressed state (L7.3 facts plus the L8.13 episode index), all three layers with verbatim episodes fetched through the L8.15 resolver, and the whole transcript. Measurement is retrieval-side: each probe carries the span its answer needs, and a configuration scores by whether that span reaches the context at all, so a failure is attributed to a layer rather than to the model. The headline metric is not recall but `misleading_context_rate` -- how often evidence is presented as sufficient while the required span is absent, which is the state in which a model confabulates fluently and is worse than an empty answer. Layering reaches 1.00 recall with 0.00 misleading context in 149 characters of evidence per probe; the full transcript reaches 0.75 at 2843 characters, nineteen times the cost, and is misleading on two probes. The compressed state alone is misleading on both verbatim probes, which is the lossiness made concrete, and the short window is misleading on everything older than itself. Only the layered configuration abstains on a probe about something never discussed, because only it has a layer that can report failing to ground a request instead of returning a paraphrase. Building it surfaced two things worth keeping: a request for exact wording names a thing *and* an aspect of it, and feeding the aspect words into episode resolution destroys coverage, so the projection is split off first; doing that also removes a substring collision, since 「そのまま」 contains 「その」 and L8.13 matches continuation markers as substrings, which made an ungrounded request read as a reference to the most recent episode. One probe strains the retrieval-side proxy and is flagged in the module rather than hidden: counting episodes is a computation, so the full transcript holds the material without holding the answer.

`episode_relation_l817_experiment.py` closes the one place where the episode layer answered confidently and wrongly. Neither 「その前の実験を続けて」 nor 「Xの後にやった方を続けて」 describes the episode it wants -- each describes a step from one episode to another -- so no similarity score can reach the answer, and L8.15 returned the latest episode for the first and X itself for the second. The fix follows the split L8.16 arrived at one level up: a relational request names an operator and an operand, so the relation phrase is removed before the anchor is resolved and the two are answered by different machinery, with edges (`followed_by`, `revises`, `reuses`) derived from the episodes rather than authored. The safety property is structural, not scored: once a relation phrase is recognised the bare-reference rule is unreachable for that query, which is asserted directly in the tests, because L8.14's lesson was that a measured rate of zero can be an accident of the probe distribution. A second guard covers relations the table cannot parse but that leave nothing else to match on -- 「二つ前の実験を続けて」 would otherwise leave 「前の」 to read as a plain continuation marker and resolve to the latest episode. On L8.15.1 this takes reference accuracy from 0.457 to 0.943 and `wrong_episode_reuse_rate` from 0.239 to 0.00.

`holdout_relation_l8171_experiment.py` is the cold measurement for it, on a third vocabulary with relation phrasings deliberately absent from the table, and it scores capability and safety separately because they are different claims. Every covered relation transfers intact -- preceding, first, following and revision all 1.00 in unseen vocabulary, with revision resolved through the edge rather than by adjacency -- and `wrong_relation_reuse_rate` falls from 0.467 to 0.067. It does not reach zero, and the residual refutes an assumption stated in the design. An unrecognised relation phrase was taken to be a missed capability rather than a hazard, on the grounds that it falls through to L8.15 and L8.15 clarifies rather than guesses. That holds only when the query names no anchor: given one, as in 「Xの直後のを続けて」 where 直後の is absent from the table, L8.15 grounds X and hands back X itself, reproducing the very off-by-one this layer was built to remove. Every wrong answer in the hold-out comes from that single path, so the phrase table turns out to be load-bearing for safety and not only for coverage. The comment claiming otherwise has been corrected; the behaviour has not, since repairing a defect against the probes that found it would turn a cold hold-out into development data.

`incomplete_operation_l818_experiment.py` generalises the defect L8.16 and L8.17 each found once. In L8.16 the episode was identified but not what to return from it, and the layer answered with a paraphrase; in L8.17.1 the anchor was identified but not the relation, and the layer answered with the anchor. Both are a request parsed in part whose understood part was executed alone -- the operand survived, the operator was dropped, and the operand came back as the result. The stronger the evidence for the operand the more confident the wrong answer, which is why 「Xの直後のを続けて」 failed precisely because X was easy to ground. The rule is therefore stated over slots rather than over Japanese: a request is parsed into a typed `QueryIR` of ANCHOR, RELATION, PROJECTION and OPERATION, and a slot that is *evoked but unresolved* blocks execution whatever else resolved. Evoked is the operative word: an ordinary reference evokes no RELATION, so nothing blocks and behaviour is unchanged; the gate fires only when the request reached for an operator the system cannot supply. It is deliberately not conditioned on whether the anchor resolved, since that is the version that produces the paradox. The cost of keying on evocation is that cue detection must be accurate, so that is structural too -- a cue character buried inside a longer compound is not a cue, which is what keeps 前処理, 後処理, 次元 and 事前 from reading as relations.

`holdout_incomplete_l8181_experiment.py` tests it on a fourth vocabulary against predictions written into L8.18's docstring before the hold-out existed. Safety is reported as a pair, because `wrong_reuse_rate` alone is satisfied by refusing everything and `unnecessary_abstention_rate` alone by guessing everything; two of the families exist purely to make an over-eager guard fail, one of them ordinary requests carrying 前処理 / 後処理 / 次元. All seven predictions held: covered relations stay at 1.00, unknown relations abstain whether or not an anchor resolved, an unimplemented operation (「一番多く使ったのは」) abstains instead of degrading into a lookup that would return one episode as if it were an aggregate, and the two safety numbers are 0.00 together. Run against the earlier hold-out the gate closes L8.17.1's residual `wrong_relation_reuse_rate` from 0.067 to 0.00 with covered accuracy unchanged at 1.00, and L8.14 and L8.15.1 are unaffected. The invariant also pre-empts the same mistake one level out: when COUNT/MODE/COMPARE arrive, a query whose value grounded but whose operation did not can no longer answer with the episode it happened to find.

`typed_operation_l819_experiment.py` resolves the OPERATION cues L8.18 left registered as unimplemented, without touching the gate: the gate answers whether a request may run at all, and this layer answers what to run it as. Operations carry signatures rather than being string handlers -- COUNT: Set[Episode] -> Integer, MEAN: Collection[Number] -> Number, MODE: Collection[Equatable] -> Equatable, ARGMAX: Set[Episode] x (Episode -> Number) -> Episode, COMPARE: Number x Number -> Comparison -- which makes a class of requests refusable before any data is read. 「実験名の平均は？」 resolves every slot it evokes and is still nonsense, because MEAN wants Number and `experiment_name` is Text; a string-matching implementation computes something, and that gap is measured as `type_error_escape_rate`. The execution condition is therefore three tests, each of which can only refuse: all evoked slots resolved (L8.18, unchanged), well-typed, preconditions satisfied. The third is kept separate from the second because ARGMAX over a field no episode recorded is well-typed and still unanswerable, and collapsing the two would hide which failure occurred -- the refusal stage is reported so they stay distinguishable.

`holdout_composition_l8191_experiment.py` tests composition rather than vocabulary: unseen *combinations* of seen operators over a fifth domain, with signatures frozen. Flat compositions work -- COUNT(FILTER(..)), MEAN(FILTER(..)), ARGMAX(FILTER(..)) and MODE all execute correctly -- and all three refusal families refuse for their own reason, giving `wrong_operation_rate` 0.00, `type_error_escape_rate` 0.00 and `invalid_execution_abstention_rate` 1.00 with `unnecessary_abstention_rate` at 0.125. The one failure is the nested case, and it is worth stating precisely: 「32x32と比べて64x64の平均実行時間は大きい？」 is COMPARE(MEAN(A), MEAN(B)), the parser is flat and first-match-wins, so 「平均」 beats 「と比べて」 and the request is read as MEAN with two contradictory filters. Both operands are recovered; only the nesting of the operators is lost, which is L8.18's lesson reappearing one level up. It refuses rather than answering, and it refuses because L8.18's precondition catches a filter that selects nothing -- a rule written for a different case holding a case it never anticipated. Left unfixed, since it was found on a cold hold-out and nesting is the subject of the query algebra rather than a parser patch.

Two things were corrected after the first run of that hold-out, both in the harness rather than in the refusal path: COMPARE's two filters select two groups, but the generic field-presence precondition was running over their intersection, so COMPARE could never execute; and the lattice sizes were assigned in a perfect three-way tie, so the MODE probe asserted a most-common value that did not exist and the system was right to refuse it.

`query_algebra_l820_experiment.py` turns the query into a tree with precedence instead of a slot record, which is what L8.19.1's nested failure needed. The grammar is Source / Filter / Project / Count / Mean / Max / Mode / Argmax / Compare, types are inferred bottom-up so a failure names the *node* rather than the cue that matched, and L8.18's gate still runs first. Two rules do the work, and both are ordinary Japanese rather than special cases: COMPARE binds loosest, so it is taken off first and its operands compiled recursively -- that alone fixes 「32x32と比べて64x64の平均実行時間は大きい？」, which the flat parser read as MEAN with two contradictory filters -- and an operand that carries a filter but no operator inherits its sibling's, since 「32x32と比べて64x64の平均実行時間は」 states the aggregate and the field once, on the second operand only. Inheritance is kept narrow because over-reach is the obvious risk: it applies only when an operand resolved a filter and no aggregate of its own.

`holdout_program_l8201_experiment.py` evaluates it with programs as ground truth rather than sentences, since "is this the right meaning" has no sharp answer while AST equality does: the program is generated first, rendered into Japanese, compiled back, and the trees compared, with values checked against an oracle computed from the episodes rather than by running the same evaluator twice. This is not a learning result and the file says so -- the compiler is hand-written, so *held out* means absent from the cases it was written against, and the question is whether the recursion works in general or whether the nesting fix was special-cased around the example that motivated it. Four shapes were in front of me while writing it; the held-out ones -- COMPARE over counts instead of means, MAX where MEAN had been, ARGMAX under a filter, two filters stacked on different fields, an aggregate with no filter at all -- score `1.00`, so the recursion is real. `wrong_answer_rate` is 0.00 and English renderings fail without computing anything, which is the language coverage measured rather than assumed.

The hold-out also surfaced a defect one level below composition. 「格子サイズ64x64の実行時間の平均を教えて」 names two fields -- 格子サイズ belongs to the filter and 実行時間 to the projection -- and the parser takes the first cue it finds, so MEAN receives Collection[Categorical]. Composition generalised; argument binding did not, and it is the same first-match mistake as L8.19's operator selection, one level down. It fails safely only because the type check refuses it: without types this would have averaged lattice-size strings. Left unfixed, since binding is the next subject rather than a parser patch.

`argument_binding_l821_experiment.py` fixes what L8.20.1 exposed: the tree was right and the arguments were wrong. In 「格子サイズ64x64の実行時間の平均」 every concept is recognised and the roles are swapped, which is missing binding rather than missing vocabulary. The fix is not a better heuristic -- replacing "first match" with "nearest match" swaps one guess for another and keeps a confident misreading possible. Instead the holes state what they require, every mention is a candidate for every hole it could type-check into, and all assignments are enumerated: exactly one well-typed binding executes, zero or several refuse. Uniqueness is the point, because it lets the layer gain capability without gaining a way to be confidently wrong. Two things follow that proximity cannot do. A value can name its own field -- in 「64x64を使った実験の平均実行時間は？」 nothing says 格子サイズ, but 64x64 occurs in exactly one domain, so the filter is forced by the value. And a request that does not determine its arguments now refuses: 「実行時間と成功率の平均は？」 offers two Number fields for one projection hole, and L8.20 silently takes the first.

`holdout_binding_l8211_experiment.py` measures it with L8.20 kept alongside, since the interesting number is not that L8.21 scores higher. Binding accuracy goes 0.333 -> 1.00 and unnecessary abstention 0.667 -> 0.00, but the result that matters is `wrong_answer_rate` 0.091 -> 0.00: L8.20 answers the ambiguous family with a number and nothing in the answer says it chose, which is the first confidently wrong output any layer has produced since L8.18. On L8.20.1 the new compiler also raises AST exact match from 0.909 to 1.00 while keeping held-out composition at 1.00, so binding was added without giving up what recursion had won.

Two corrections belong in the record. The first is a regression this layer introduced and then removed: a new "named field that cannot fill the hole is a type error" rule fired ahead of L8.20's ellipsis inheritance, so in 「格子サイズ32x32と比べて…」 the baseline's filter field was reported as a failed projection; inheritance now outranks it. That family's number is therefore development-informed rather than cold, and the refusal families were unaffected by the change. The second is a measurement fix, not a compiler one: conjunctive filters commute, so FILTER(FILTER(s, seed), lattice) and FILTER(FILTER(s, lattice), seed) are the same set, and comparing raw renderings counted that as a wrong tree. AST equality is now taken over a canonical form that orders commutative filter chains.

`semantic_proposer_l822_experiment.py` adds the first learned component, with proposal rights and no authority. L8.18 through L8.21 built a pipeline whose every stage can only narrow what is allowed to run, and the price is a closed world: 「64x64で走らせたケースについて処理時間をならして」 is a mean, and the compiler has never heard of 「ならして」. The purpose of learning is to turn some of those safe abstentions into correct executions without creating a single wrong one, so a proposal of MEAN at 0.72 does not run MEAN -- it puts MEAN into the candidate set, and the request executes only if the symbolic pipeline then yields exactly one well-typed program. A confident wrong proposal costs coverage, never correctness. Two choices keep that honest: the proposer fires only where the hand-written cues found nothing, so every earlier benchmark is unchanged and any gain is coverage that did not exist before; and candidates are taken by margin rather than argmax, the same discipline L8.15 introduced, applied to a learned score. The model is a character n-gram classifier trained on generated (surface form, label) pairs. It cannot invent a meaning for a word with no subword overlap with anything it has seen; what it can do is carry 「ならす」 to 「ならして」, and calling that anything more would overstate it.

`holdout_language_l8221_experiment.py` holds out wording and shape independently, because lumping them together hides which one the learner helped with, and keeps L8.21 on the same probes. Unseen-language execution goes 0.00 -> 0.75 and unseen composition 0.50 -> 1.00, with `wrong_answer_rate` and `unsafe_execution_rate` both 0.00 and refusal accuracy 1.00; `safe_coverage_gain`, correct minus wrong, rises 0.545 -> 0.909. Two families exist to stop the guard being graded generously. 「ピークをならして」 carries evidence for MAX and for MEAN at once, both type-check over a Number field, two well-typed programs survive and the request is refused -- a proposer with authority would run whichever scored higher, which here is a coin flip between max and mean. And wording with no subword overlap buys no coverage at all, which is the honest outcome rather than a guess.

One probe is refused that a reader would answer, and it points at the next improvement rather than a bug: 「64x64で走らせた分のランタイムの値をアベレージ」 scores MAX 0.516 against MEAN 0.484 and runtime 0.513 against success_rate 0.487. The classifier scores the whole request, so evidence from ランタイム and アベレージ is diluted by the surrounding words until neither margin clears. `span_grounded_proposer_l823_experiment.py` scores the span that carries the evidence instead of the whole request. `holdout_span_l8231_experiment.py` measures it on fresh probes, since L8.22.1 became development data the moment its refused case was used to design this layer, and the result is a tie. `evidence_arbitration_l824_experiment.py` stops choosing a witness. L8.23.1 had measured the two sensors as a tie with different failures -- spans are sharp where a phrase is covered and blind where it is not, the sentence is robust to thin overlap and cannot separate two pieces of evidence sitting in one string -- so picking one, even per slot, would be one more heuristic of the kind this project keeps removing. Admitted candidates go to L8.21 together and the uniqueness rule decides, unchanged. The strength requirement is what separates this from a union, and L8.23.1 shows why a union fails: in the dilution case the sentence reading is MAX 0.516 against MEAN 0.484, which is contention rather than evidence, and merging candidate sets would put MAX back beside the span's MEAN and restore the ambiguity grounding had resolved. `holdout_arbitration_l8241_experiment.py` builds its families around which sensor can see each case and reports capability complementarity alongside accuracy, since L8.22 and L8.23 scored the same on fresh probes while disagreeing about which requests they could handle. `evidence_calibration_l825_experiment.py` replaces L8.24's `WHOLE_STRONG = 0.75` with an estimate. That constant works and it was read off one observed distribution -- decisive readings near 1.0, contended ones near 0.5, so 0.75 sat in the gap -- and nothing guarantees the gap is there in another vocabulary. `holdout_calibration_l8251_experiment.py` asks whether the estimate agrees with the constant and where it does not, and the answer is reported as it came out, including a null. The boundary is one band lower than 0.75 -- whole-sentence operator readings at 0.6 are right 95% of the time and the fixed rule rejects them. `structural_sensor_l826_experiment.py` adds a third sensor built so that it cannot repeat the other two. Fusion changes with it: L8.24 admitted every strongly-supported candidate and let uniqueness decide, which is safe and, with two agreeing sensors, often blind -- two field spans in one request are both admitted and the request refused even when the sentence plainly attaches the operator to one of them. A candidate is now also dropped when its supporting sensors are a strict subset of a rival's. That is comparison, not authority: no sensor outranks another, and equal-sized disagreeing supports are both kept.

`holdout_structural_l8261_experiment.py` measures the four cells. Execution accuracy goes 0.600 -> 1.000 with refusal accuracy 1.00 and `wrong_answer_rate` and `unsafe_execution_rate` 0.00. `evidence_graph_l827_experiment.py` stops passing candidates along as two sets and builds a graph instead: `MEAN --bind--> success_rate --filter--> 64x64`, where nodes are *grounded* -- a label at a span, or a span with no label -- and every edge records which sensors witnessed it, from which span, at what strength. The motivation was a failure, not a tidier diagram. An **unnamed argument becomes visible** as an `UNKNOWN` node, and an operator that needs a field refuses rather than substituting a legible one. **Attachment comes off syntax rather than proximity**: の closes a modifier chain so 「サクセスレートの値」 is one argument instead of a far 「サクセスレート」 and a near 「値」, and を marks the direct argument so 「Aを Bのかわりに ならす」 is about A however close B sits to the head. **A plural argument becomes visible**: と coordinates, the algebra has no node for two projections, and the edge remembers it was built across と even when only one conjunct was legible. And **the sensors complete each other across one edge** -- structure says where without saying what, the sentence says what without saying where, so when the head governs an unlabelled span and exactly one ungrounded whole-sentence field exists, the two halves determine the edge and it is witnessed by both. Uniqueness is the whole safety argument for that repair: with two fields in play the sentence score splits, nothing clears `WHOLE_STRONG`, and the repair is unavailable in exactly the case where it would be guessing. Authority is unchanged throughout -- the graph proposes one binding and L8.21's uniqueness rule still decides whether anything runs.

`holdout_graph_l8271_experiment.py` reports two suites, because the hand-written families are development-informed: the wrong answers above were found on those sentences, so their L8.24/L8.26 column is a diagnosis rather than an estimate. One **frozen expectation is reclassified**: L8.26.1 scores 「64x64のケースの成功比率を処理時間のかわりにならした」 as a required refusal, on the grounds that two field candidates were each strongly attached and neither dominated. What moved is the claim that the sentence is inherently ambiguous, which was a statement about the sensors of the time. And one **latent defect** surfaced that had been invisible for three layers: both new refusals were first keyed on L8.19's `OPERATIONS` table, which predates MAX, so `needs_field("MAX")` answered False by default and neither guard applied to a MAX request -- six wrong answers on the sweep, from a default that failed open. The test pins the direction rather than the operator.

What is left undone is the residual 12.5%: the graph locates an argument, correctly refuses to guess it, and still cannot name it. Naming an unknown phrase from the structure it sits in is lexicon acquisition, which is the next layer.

`lexical_hypothesis_l828_experiment.py` takes that residual and implements **half** of what it needs, on purpose. Acquiring a word is two capabilities -- generating hypotheses about what an unnamed span denotes, and promoting one of them into the lexicon -- and measured together a good generator with an unsafe promoter scores the same as a bad generator with a cautious one. So this layer generates and promotes nothing: the classifiers are not retrained, the form banks are not written to, and `run_hypothesis_query` returns L8.27's decision *by construction* -- it calls `run_graph_query` and hangs hypotheses beside the answer rather than into it, with no branch that could alter one. That separation is what lets the layer report the cost a promotion stage would inherit (`decidable_precision`: were a later stage to promote every hypothesis this one finds unique, how often would it be wrong) without paying it. It also buys something concrete: a hypothesis may rest on evidence far too weak to execute on, because it is not executing. The span sensor rejects 「成功の比率」 below `SPAN_COVERAGE` and must, since acting on thin overlap is how L8.23 learned to dilute -- but the same thin overlap is perfectly good grounds for *suspecting* success_rate once suspecting costs nothing. Four sources, each independently ablatable: `type` (the operator's projection hole, so MEAN's argument is a Number whatever it looks like), `contrast` (「Xではなく Y」 asserts Y is not X, with the particle supplying the relation and a labelled sibling the term), `attestation` (`energy_error` is in the schema and in no episode, so it is a poor guess for a phrase someone wants averaged), and `subword` (n-gram overlap with **no floor**, scored over every substring).

`holdout_lexicon_l8281_experiment.py` crosses two axes -- overlap against zero overlap, contrast against bare -- so that spelling and structure can be told apart. The `ZERO_*` families use invented forms whose absence of shared n-grams is *checked* by `assert_zero_overlap` rather than asserted in prose. On 89 probes: `hypothesis_recall` 1.000, `top1_accuracy` 0.905, MRR 0.952, `decidable_rate` 0.667 at `decidable_precision` 1.000, with `false_hypothesis_rate`, `wrong_answer_rate` 0.000 and `execution_invariance` 1.000. The cell that matters is `ZERO_CONTRAST`: recall 1.0, top1 1.0, decidable 1.0 -- **a word the system has never seen, named from the type hole and one contrastive particle, with subword coverage exactly 0.00**. The ablation makes that non-anecdotal: removing `subword` leaves `decidable_rate` and `decidable_precision` untouched (0.667 / 1.000) and costs only ranking in the bare overlap cell, while removing `type`, `contrast` or `attestation` takes decidability to zero. Spelling is not what is doing the work.

The layer's own result is the limit it found. With only two attested Number fields, "exclude one by contrast" and "name the other" are the same operation, so `decidable_precision` 1.000 might be counting the schema rather than the mechanism. That is testable, so it was tested rather than caveated: `widen_store` attests a third Number field and the sweep is re-run. **`decidable_rate` collapses 0.667 -> 0.000 and `top1_accuracy` 0.905 -> 0.429, while `hypothesis_recall` stays 1.000.** The generator degrades into indecision, not into error -- the safe direction -- and the number says exactly what a promotion stage still lacks: evidence that separates candidates *within* the type-admissible pool, which contrast cannot do because it can only remove one. One honest reporting note: `top1_accuracy` in the bare cells is chance among the surviving candidates, since nothing is left to rank with; `decidable_rate` 0.0 there is the number that actually describes the behaviour.

`cross_context_identification_l829_experiment.py` takes that failure at its word. Recall stayed 1.000 while decidability went to zero, which means the truth was never lost -- it stopped being *separable*. A candidate set that still contains the answer is an unfinished measurement, and measurements can be continued, so meaning becomes a latent variable narrowed over episodes: `H_{t+1}(w) = H_t(w) ∩ C(e_t)`, with the state read off the set and nothing else -- `|H| == 1` DECIDABLE, `|H| == 0` CONTRADICTION, `|H| >= 2` UNRESOLVED. That keeps L8.18's fail-closed rule by construction rather than by a new guard, and there is no threshold anywhere in the layer. Four constraint sources, all label-free and all already present: `TYPE` (the projection hole, which separates Numbers from everything and nothing within them -- precisely why one observation was never enough), `CONTRAST` (「Xではなく w」 removes one candidate, so K-1 observations for K candidates: **linear**, and the baseline to beat), `RANGE` (a literal must lie inside the field's attested range, which *splits* the set instead of shaving it), and `DISTINCT`. Because a split carries more than a shave, which context to seek next becomes a real decision, and `EIG(q) = H(M|D) − E[H(M|D,q)]` over a uniform prior on the survivors makes it -- the same uncertainty-reducing intervention as the earlier experiment planners, with a word's meaning as the latent variable instead of a state of the world.

`holdout_identification_l8291_experiment.py` sweeps **K, the number of same-typed fields**, over three arms. `single` reproduces L8.28 exactly (decidable 1.0 at K=2, 0.0 from K=3) -- the check that the suite measures the same thing. `cross` reaches `decidable_rate` 1.000 at every K from 2 to 50, at a cost of exactly K observations. `eig` reaches it too, in 1.0 / 2.0 / 2.6 / 3.0 / 3.0 / 3.0 observations. `false_acquisition_rate` is **0.000 in every cell of every arm**; `contradiction_detection_rate` is 1.000 with no false contradiction on a consistent pair.

The layer's real finding is that **the scaling law belongs to the world, not to the algorithm**, which is why two synthetic geometries are run. In `banded` (fixed-width ranges sliding past each other) any literal localises to a constant-size block however many fields exist, so EIG's cost stops growing with K -- flat at 3.0 from K=10 to K=50 while `cross` goes to 50.0. In `nested` (ranges contained in one another) a field whose range sits inside every other field's **cannot be separated by any literal at all**: every value it could truthfully be compared against is admitted by everything above it. Only CONTRAST separates those, one at a time, and EIG degrades to near-linear (26.6 at K=50) with an observation mix dominated by CONTRAST. The twin control is the limit of that argument: two fields sharing a type and a range and nameable by nothing stay UNRESOLVED under every arm, while an ordinary field in the same universe still resolves. That control caught a real bug first -- contrast probes were being generated for fields no sentence can name, which resolved the twins and made the control vacuous.

The end-to-end section is what stops this being a simulation. On the widened store, the invented word 「フガ率」 is narrowed across **two actual requests** parsed by L8.27's graph and L8.28's sources: the recurring word is found by longest common substring across the differing spans (`0.5以上のフガ率`, `フガ率`) rather than assumed, the first request contributes TYPE and CONTRAST and leaves `{energy_error, success_rate}` -- UNRESOLVED, exactly L8.28's wall -- and the second contributes a RANGE constraint at 0.5 that only one of them admits. `success_rate`, acquired. The refused request then goes **ABSTAIN -> ANSWER** with the correct program, `false_acquisition` and `wrong_answer` both false, and retracting the entry returns the system to ABSTAIN -- acquisition is reversible, because a promotion that cannot be taken back is not safe to make. This is the first point in the project where something learned about language changes what executes, so the opening is deliberately narrow: only where L8.27 already refused for want of a name, only for the exact span it could not label, only from a singleton belief, with L8.21's compiler, L8.19's type check and the uniqueness rule all untouched downstream.

`lexical_revision_l830_experiment.py` addresses the dangerous half of that: once a belief became a singleton, L8.29 held it true forever. A word acquired from two contexts is a conclusion drawn from two contexts, and the third can disagree. The obvious repair is the wrong one -- flipping the entry when a contradiction appears trusts the newest observation most, and the newest observation is precisely the one corroborated least. So the rule is `contradiction != immediate remapping`: a contradiction **suspends** rather than rewrites. The lexicon becomes a state machine, `UNKNOWN -> HYPOTHESIS -> ACQUIRED -> DISPUTED -> REVISED | REVOKED`, in which only ACQUIRED and REVISED carry execution authority, so L8.18's fail-closed rule now holds over the lexicon's *time evolution* and not only within a request.

Revision is threshold-free. No weights, no decay, no confidence number: the belief keeps every observation with its provenance and asks which **maximal** subsets are jointly satisfiable, preferring those that discard the fewest. One repair with one surviving candidate revises to it; one repair that rules out the old meaning without naming a replacement revokes; several disagreeing repairs leave it DISPUTED. That arithmetic produces the intended behaviour without anyone stipulating it -- one contradicting observation against one supporting observation is a tie of equal-cost repairs, so it suspends and cannot flip, while a second corroborating one breaks the tie because discarding two costs more than discarding one. **One disagreement suspends; two agreeing disagreements revise, and nothing in the code counts to two.**

`holdout_revision_l8301_experiment.py` insists on both halves, because a layer that revises eagerly scores perfectly on correction and destroys correct lexicons, while one that never revises scores perfectly on maintenance and keeps its mistakes. MAINTAIN and CORRECT therefore have the *same shape* and different truths -- nothing in the belief can tell them apart when the contradiction arrives, only what comes afterwards can. On the real universe: `revision_accuracy` 1.000, `contradiction_detection_rate` 1.000, `false_revocation_rate` 0.000, `time_to_suspend` 0.0, and the two invariants **`wrong_answer_during_dispute` 0** (a query is issued after every single observation, and while the belief is not authoritative the executor refuses) and **`irreversible_false_learning_rate` 0.000**. On a generated sweep over universes of 3, 4, 6 and 10 fields with the stray observation slid through every position and every field taking a turn as the truth, `revision_accuracy` and `correct_reacquisition_rate` are both 1.000 at every size with the invariants still at zero. STALEMATE ends DISPUTED and REVOKE ends REVOKED, both silent -- a belief can be suspended forever, and that is the correct end state rather than a failure to converge.

Two things are worth reading closely. The sweep is run on a **disjoint** geometry, because that is the only regime in which a claim about revision is testable at all: with overlapping ranges a stray observation can be consistent with the truth, so it never contradicts and a run that ends wrong was never given the evidence to know. That case is measured separately on a `banded` sweep as `undetected_noise_rate` (0.333 at K=3 falling to 0.100 at K=10) and reported as what it is -- L8.29's identifiability result again, not a revision failure. **Noise you cannot detect is noise you cannot revise.** And the suite caught a real defect in the belief machine: without a revision producing a *new belief base*, the raw intersection stays empty forever and the very next **agreeing** observation re-fires the contradiction, oscillating REVISED -> DISPUTED without end. The discard is provisional rather than destructive -- the full log is kept and the next contradiction reconsiders all of it, including what an earlier repair set aside.

`semantic_identifiability_l831_experiment.py` steps back from all three. L8.28's third Number field, L8.29's `nested` wall and twin control, and L8.30's `undetected_noise_rate` are the same phenomenon called three names: two meanings are **observationally equivalent** when `m_i ~_O m_j` iff every available observation treats them alike. This layer computes those classes from the schema and the observation family alone, **before** any learning happens, and returns a verdict with the classes rather than a flag -- because "cannot be decided" is far less useful than "cannot be decided *between success_rate and energy_error*". The three verdicts are three different situations: IDENTIFIABLE means more evidence will settle it, PARTIALLY_IDENTIFIABLE means the current observation language cannot but a small extension of it could (a gap, which more of the same evidence will never close), and STRUCTURALLY_UNIDENTIFIABLE means no extension in the pool splits the class at all (a wall).

One correctness point shapes the whole design: **ruling out is directional**. Signatures differing at some observation means exactly one of the pair survives it -- but a world whose word means the one that *fails* that observation can never produce it, so that separation is unavailable there. The symmetric relation is therefore optimistic, and it is reported for the universe-wide picture while every verdict is built from `reachable`, the set a truthful stream can never narrow past. `CONTRAST(runtime_seconds)` is the clean case: it separates runtime from everything except when runtime is the answer.

`holdout_identifiability_l8311_experiment.py` refuses to score the analysis on its own terms. L8.31 runs **first**, its predictions are recorded, and then L8.29 and L8.30 run and the two are compared. `false_identifiable_rate` **0.000** (the invariant -- promising learnability the later layers cannot deliver would have L8.29 acquire on partial evidence and hand L8.30 a case it cannot correct; the reverse error only costs coverage), `indistinguishable_pair_recall` 1.000, `equivalence_class_accuracy` 1.000 -- the set L8.31 says a truthful stream can never narrow past is exactly the set L8.29's exhaustive `cross` arm ends with -- `minimal_distinguishing_set_accuracy` 1.000, and `predicted_vs_observed_detectability` 1.000.

That last one took two attempts and the correction is the interesting part. Detectability in principle is not the same as a contradiction being **recorded**: a stream whose evidence conflicts still produces nothing if the belief never committed to a meaning first, so the two have to be predicted separately. Pure identifiability gives `predicted_undetectable_rate` **0.174** -- exactly the `undetected_noise_rate` L8.30 reported as a property of its own runs, recovered here from the schema with no belief machinery, which is what makes them one structure rather than two demonstrations. Adding the sequencing condition gives the observed 0.500, and a six-line prefix-intersection predictor that accounts for both agrees with L8.30 on every run.

Minimal distinguishing sets are checked by using them: the proposed observations are added to the language and `reachable` is recomputed. Mean size 1.4, and 0.823 of them resolve to a singleton -- the rest only narrow the class, and `resolves` reports that honestly rather than counting a refinement of `{a, b, c}` into `{a} | {b, c}` as an answer. Finally, the control no amount of data passes: the twins at N = 10, 100, 1000 and 10000 stay a class of two while an ordinary field in the same universe is a singleton at every N, and L8.31 called both before any evidence arrived. That is what finally separates **not enough data yet** from **the language cannot say it** -- and it settles which question polysemy is: a surface whose evidence will not reconcile is two words only if the two meanings are separable, because splitting an unidentifiable pair invents a distinction the world does not support.

`active_observation_l832_experiment.py` turns that into a next action. If L8.31 can say which single observation would split a class, the problem stops being "gather more evidence" and becomes "gather *this* one" -- and, the half that matters more, "gathering anything at all is pointless here, so stop". The objective is written over the candidate set rather than over entropy, `o* = argmin_o E[|C after o|]`, because that is what the stopping rule needs to read: a query whose two outcomes do not split `C` leaves `E[|C|] = |C|` **exactly**, so "useless" is an equality rather than a threshold on a score, and a state where every available query is useless is `STRUCTURALLY_UNRESOLVABLE` -- provable in one pass over the pool before a single question is asked.

**Asking is strictly stronger than being told, and the gap is measured rather than claimed.** L8.31's `reachable` is the passive regime the earlier layers lived in: an observation arrives only when the meaning satisfies it, so a meaning is never narrowed by what it fails. A query has two outcomes and the negative one is evidence too. Measured on magnitude comparisons alone -- the full pool's CONTRAST probes make every meaning passively identifiable, so the gap would read as zero for the wrong reason -- `active_vs_passive_gain` is 26 meanings across the worlds, and the pattern is exactly L8.29's `nested` finding arriving from the other side: 7 of 10 meanings in `nested/K10` cannot be narrowed passively, because every literal they could truthfully be compared against is admitted by everything above them, and only a *negative* answer separates them. The twins are unmoved under both regimes. Active querying buys reach, not miracles.

**Greedy is checked against optimal rather than assumed to be it.** Minimising expected size one step at a time is the standard move and is known not to be optimal in general, so for every world small enough to enumerate the whole decision tree is walked and `E[T]` computed exactly by memoised recursion. `greedy_vs_optimal_regret` is **0.0** in all eleven enumerated worlds -- a measurement about these worlds, not a theorem, and the tree was enumerated precisely because assuming otherwise would have been the easy mistake. "Not enumerated" and "no policy exists" print differently, which they did not until the distinction was forced.

`holdout_active_l8321_experiment.py` reports `active_resolution_rate` 0.978 (everything except the twins, which are the 2 that should not resolve), `false_resolution_rate` **0.000**, `impossible_query_avoidance_rate` **1.000** with `wasted_queries` **0** (measured, not assumed -- a zero nobody looked for is not evidence), 2.56 observations to resolution, and `predicted_vs_actual_reduction` 0.0. The safety invariant is structural: both branches of a query keep the true meaning, so the candidate set always contains the answer and a singleton can only ever be the right one.

That argument holds only because a NO is exact, and an earlier draft proved the point the hard way -- approximating the negative branch with a hand-picked CONTRAST resolved 「フガ率」 to the wrong field, which is the false resolution the layer claims is impossible. Negation is now a first-class observation, so every layer that narrows through `constrain` handles it without changing.

The loop closes end to end on a real request. The graph refuses 「64x64のケースで処理時間ではなくフガ率をならして」 for want of a name; L8.31 reports `{energy_error, success_rate}` and PARTIALLY_IDENTIFIABLE, so the word is worth asking about; L8.32 picks the question and puts it in words -- 「フガ率」は success_rate とは別の指標ですか？ -- and the answer, a NO, goes back in as an observation; L8.30's belief reaches ACQUIRED on `success_rate`; and the same request now answers with the correct program, after exactly one question. 分からない → なぜ分からないか → 何を観測すれば分かるか → 実際に観測する → 意味を更新する.

`greedy_counterexample_l8322_experiment.py` is the audit that decides what that `regret = 0` meant. It adds no capability; its only output is a fact about the previous layer. The search maximises `R = E[T_greedy] − E[T_optimal]` at two tiers, and the answer is both halves at once. Over **every** interval world on a small grid (1365 at K=4, 3003 at K=5) and a thousand random ones, greedy is exactly optimal. Over arbitrary set systems it is not: the smallest counterexample found has six meanings and five queries, where greedy pays 17/6 against the best policy's 8/3. Every set system with five meanings or fewer is clean, exhaustively, so six is where counterexamples *start* rather than where this search happened to look. **The zero came from the geometry, not from the rule** — which is the same distinction L8.29 and L8.31 kept arriving at about identifiability, reached here about planning. Tier A alone would have read as "greedy is fine" and Tier B alone as "greedy is unsafe"; the pair says something narrower and true. The audit runs on its own small reimplementation of both policies, since running it through the code being audited would prove nothing about that code, and a test pins the two together on interval worlds so the generalisation is faithful rather than merely similar. (Numbering note: `l8321` was already the active-observation hold-out, so this went in as L8.32.2.)

`epistemic_dialogue_l833_experiment.py` closes the last gap, which asking created. Once the agent asks a question, the next thing the user says is 「いいえ」 — and routing that as a fresh request is exactly the failure this project started from, a turn interpreted without the state that gives it meaning. So the question is not a side effect: it is state. Asking suspends the goal inside the episode; the reply is interpreted **relative to the pending question**, converted to an observation, folded into L8.30's belief, and only then does the suspended goal run again. The original request is never re-derived, because it was never finished.

Three properties carry the layer. **Only three kinds of reply commit anything** — a plain yes, a plain no, and a correction that names the field outright. 「たぶん違う」, 「分からない」 and 「質問の意味が分からない」 commit *no observation at all*, and `UNKNOWN` is the case that matters most: reading "I don't know" as a no is the obvious shortcut and it silently manufactures evidence the user never gave, in the direction that makes the next answer look confirmed. The cue table is ordered longest-first and the order *is* the rule, since 「たぶん違う」 contains 「違う」. **An answer binds to the question that is pending, or to nothing** — a reply arriving after the goal already resumed binds to nothing rather than to the question it would have answered, which is the stale-binding accident that only exists once questions have state. **An interruption ends the goal without evidence**, so a cancelled task leaves no trace in what the system believes words mean.

`holdout_dialogue_l8331_experiment.py` runs ten conversations chosen so that every one would pass a naive implementation that treats any reply as an answer: `answer_to_question_binding_accuracy` 1.000, `suspended_goal_resume_accuracy` 1.000, `commit_exactness` 1.000, and the four invariants `wrong_observation_commit_rate`, `false_resolution_rate`, `stale_question_answer_binding_rate` and `unnecessary_question_rate` all **0.000**. The `UNKNOWN_THEN_ANSWER` conversation is the one to read: 「分からない」 retires the question and a different one is asked, and the 「はい」 that follows binds to the *new* question and resolves the word correctly — the retired question is not the one the next reply answers. `NO_QUESTION` is the control that keeps the rest honest, since a layer that asks about everything can buy any resolution rate it likes.

With this the series closes on the problem it opened with. L8.13 gave episodes their own state so old work would stop leaking into new; L8.27–L8.32 built the machinery to notice a word it cannot read, decide whether the word is learnable at all, and choose the one question that would settle it. L8.33 is where those meet: the agent holds what it does not know, asks the question that most reduces it, remembers what its answer was an answer *to*, updates only that evidence, and returns to the work it suspended.

`joint_inference_l834_experiment.py` removes the last strong assumption: that there is one unknown word. 「フガ率がホゲ尺より大きいケースの平均を出して」 breaks it twice over, and solving each word separately throws away what carries most of the information — **the relation between them is itself evidence**. With attested ranges of runtime 8.0–51.75, success_rate 0.40–0.75 and energy_error 0.001–0.024, 「より大きい」 is a strict order that rules out three of the six ordered pairs before either word is looked at, and the order comes from the store rather than from a vocabulary.

So the belief is over assignments: `B = {(m₁, m₂) ∈ C₁ × C₂ : types, relations and observations all hold}`. The rule that follows is the one this project keeps rediscovering in new clothes — **a unique marginal is not a unique assignment**. When the belief is `{(runtime, success), (success, runtime)}`, both surfaces are "narrowed to two" and the correspondence is exactly what is unknown; reading the marginals would report progress and run the wrong program. Execution waits for `|B| == 1`, which is L8.21's uniqueness rule lifted from one hole to a tuple of them, and `MARGINAL_ONLY` is a state rather than a rounding error so the difference can be reported.

`holdout_joint_l8341_experiment.py` is built so that a solver which merely ran L8.29 twice would score zero on the number that matters. In the `JOINT_ONLY` families both surfaces carry the same evidence and are each ambiguous between the same two fields — word-at-a-time inference finishes with two candidates apiece and nothing decided — while the order admits only one pairing, so the assignment is unique and neither marginal is. `independent_vs_joint_gain` is **2**, `joint_resolution_accuracy` 1.000, `false_joint_resolution_rate` **0.000**, and `MARGINAL_TRAP` sits at `MARGINAL_ONLY` with `marginal_trap_abstention` 1.000. `INDEPENDENT_ENOUGH` is the control in the other direction — where word-at-a-time already succeeds the joint solver must agree rather than quietly differ — and `IMPOSSIBLE` produces a contradiction instead of an arbitrary pick.

Question planning moves with it. A relational question — 「フガ率とホゲ尺は別の指標ですか？」 — is a candidate beside the per-word ones, and whether it wins is left to the planner. It does: the first question chosen is relational, and the pair resolves in **2** questions where per-word planning needs **3**, both arriving at the same meanings. The same fact read positively is that the marginal trap is *escapable by asking about the pair* — with no per-word question available at all, one relational question still settles it, because the correspondence is what was undetermined. End to end, two words are acquired at once and an ordinary single-word request then goes ABSTAIN → ANSWER with the correct program.

`contextual_polysemy_l835_experiment.py` asks the question that comes *before* letting a surface hold two meanings: does this word need to be conditioned at all? Registering two senses is easy and proves nothing — an implementation that adds a sense whenever evidence disagrees reaches perfect training accuracy by never being wrong about anything. And a contradiction is not an answer, because L8.30 already showed it has at least three readings that look identical at the moment the disagreement lands: the word means one thing and an observation was wrong (**noise**); it meant one thing and now means another (**revision**, explained by *time*); or it means different things in different situations (**polysemy**, explained by *context*). So the state machine refuses to jump — `SINGLE → DISPUTED → POLYSEMOUS` only when a stable conditioning exists, and back to DISPUTED when none does.

**The partition is never assumed.** Writing "in a simulation context it means A" would put back the hand-written table this project has spent twenty layers removing. The evidence is asked instead whether *some* conditioning makes the contradiction go away — the whole set is inconsistent, yet every block of some partition is internally consistent with a meaning of its own — and which variable does the partitioning is read off the data. Two rules stop it becoming the sense-splitting machine it could so easily be. **A block of one explains nothing**: a partition whose block holds a single observation says exactly what "that observation was noise" says, with an extra parameter, so it is not admitted — no threshold needed, because one is not a pattern. **An explanation both variables fit is no explanation**: if the time split is also context-pure and the context split also time-contiguous, the data cannot tell revision from polysemy and the honest report is that it cannot. A split is also refused outright when L8.31 says the two senses sit in the same observational equivalence class.

`holdout_polysemy_l8351_experiment.py` runs the four ways evidence can disagree plus two controls, because a suite containing only genuine polysemy measures nothing: `false_sense_split_rate` **0.000**, `missed_polysemy_rate` 0.000, `context_conditioned_resolution_rate` 1.000, `revision_vs_polysemy_accuracy` 1.000, `wrong_answer_rate` **0.000**, `explanation_accuracy` 1.000. REVISION and TRUE_POLYSEMY have the same contradiction and are separated by which variable explains it — in REVISION both contexts appear on both sides of the change, in TRUE_POLYSEMY the contexts interleave in time.

The ablation is the strongest claim available. Running the same evidence with the context labels erased makes `TRUE_POLYSEMY` go **POLYSEMY → UNEXPLAINED** and stop resolving, while NOISY_MONOSEMY, REVISION and MONOSEMY are completely unaffected. Context was not a convenience that improved things; it was the variable the meaning depended on. (A detail worth keeping: AMBIGUOUS goes **AMBIGUOUS → REVISION** when the labels are erased — with nothing to compete against, time explains it on its own, which is exactly why it was ambiguous while context existed.)

And the context is not new. It is the episode — L8.13's boundary, introduced twenty-two layers ago to stop old work leaking into new — arriving here as the conditioning variable for word sense. `Episode → Context → Sense`.

`cost_aware_dialogue_l836_experiment.py` fixes what L8.32 left incomplete: a yes/no and a five-way choice are both "one question" and are not the same thing to answer. The obvious repair — `gain − λ·cost` — smuggles in a constant nobody can justify, and this project has spent a dozen layers removing exactly those. So there is no λ. Questions are compared **lexicographically**: `q ↦ (resolution capability, expected remaining ambiguity, cost)`. First, do not ask something that leaves a branch permanently stuck — a veto, not an optimisation, because no amount of cheapness redeems spending a turn to arrive nowhere. Second, shrink the hypothesis space most. Only where those tie does cost decide, and **cost is not a number either**: it stays a vector `(turns, |answer space|, needs a context recall)` compared by Pareto dominance. A three-way choice in one turn and two yes/no questions are genuinely incomparable, and inventing a weight to rank them would be inventing the answer — so when several survive, the planner reports `MULTIPLE_OPTIMAL` and hands them over rather than picking.

**What L8.35 makes newly possible is a question about the model rather than the meaning**, and that turns out to be a capability claim rather than a price one. In the AMBIGUOUS state the space is exactly `{POLYSEMY, REVISION}`, and the two predict *the same meaning for every observed context* — so the number of informative meaning questions is **0**. Not "fewer", not "worse value": asking what the word means cannot separate them at all, and the target of questioning has to move to 「この語の意味は、時期によって変わりましたか、それとも場面によって違いますか？」. Getting that right needed two corrections. Capability was first written as something to maximise, which made balanced-but-uninformative questions win; and a REVISION hypothesis was answering meaning questions from its own block labels rather than from what it predicts for each observed context, which made it separable by a question it actually answers identically. Predictions are now computed from the evidence, and the identity is visible to the planner instead of being asserted.

The hypothesis space also inherits L8.30's rule: an account that **discards** observations is strictly worse than one that explains all of them, so a NOISE reading survives only while no conditioning fits. Without that, a worse account dilutes the value of every question.

`holdout_cost_dialogue_l8361_experiment.py` separates the three comparisons so passing cannot come from being good at one: `false_resolution_rate` **0.000**, `avoidable_interaction_rate` **0.000** and `excess_cost_given_equal_resolution` **0.000** — the last two exist to fail the planner that asks about everything, since any resolution rate is reachable by spending turns. `EXPENSIVE_BUT_NECESSARY` is the cell where the three-way choice wins *despite* the larger answer space, because it finishes in one turn and so never reaches the cost comparison; `STRUCTURE_ONLY` is where the combined model question asks for the same information while also requiring a context recall and is therefore Pareto-dominated and dropped. `IMPOSSIBLE` is checked on a constructed space and disclosed as such, because in this hypothesis language it appears unreachable from evidence — the planner can always enumerate the live meanings itself, and two accounts that predict the same thing everywhere and share a model are the same object. That is the same disclosure L8.24 made about constructed conflict evidence, for the same reason: a rule that is never tested has not been tested.

`nway_semantics_l837_experiment.py` asks whether the rule generalises rather than whether the code scales. L8.34 solved two unknown words together and the gain was real, but two is the number where a cartesian product is small enough that nothing has to be clever. So: `B₀ = M₁ × … × Mₙ`, `B_{t+1} = {b ∈ B_t : C_t(b)}`, execution gated on `|B| = 1` and nothing else — and **adding no new safety rule as n grows is itself the thing under test**. A layer that needed a fresh threshold at n=4 would have shown that L8.21's uniqueness rule was a two-variable convenience.

`holdout_nway_l8371_experiment.py` runs two phases, because succeeding at a size you could have enumerated proves nothing about the method. At **n = 3..5** the propagating solver is checked against an exhaustive oracle for exact agreement — `oracle_agreement` **1.000**, same solutions and same verdicts. At **n = 6, 8, 10** the same problems grow past enumeration and only the states visited are counted: at n=10 the product holds **10,000,000,000** assignments and a resolving family visits **10 states** — one per word, the signature of propagation rather than of search. `false_joint_resolution_rate` **0.000**, `verdict_accuracy` 1.000, worst states/|M|ⁿ **8.4 × 10⁻⁴**. Agreeing with brute force and then not doing brute force is what separates a constraint solver from a loop over a product.

`GLOBAL_ONLY` is the family that decides it, and the claim is stated as the comparison that establishes it: with the n-ary constraint removed the problem has several solutions, **every** one-word marginal is plural and **every** two-word marginal is plural; restoring it leaves exactly one assignment. A world like that cannot be solved by being good at words or at pairs. It needs a constraint that decomposes into no set of binary ones, and the domain supplies it — 「1つ目が残りの合計より大きい」 relates all n at once. `SYMMETRIC` is the control that cannot be passed by trying harder: when the constraints are invariant under permuting meanings the solutions come in orbits, and `symmetry_broken_rate` is **0.000** at every n and under piled-on evidence of the same symmetric kind. Resolving there would mean inventing the distinction rather than finding it.

One thing the run corrected, kept in the code as a disclosure. `GLOBAL_ONLY` first collapsed to CONTRADICTION from n=5, and the cause was the world rather than the solver: with evenly spaced disjoint ranges the highest field's maximum stops exceeding the sum of the others' minima, so the sum constraint becomes unsatisfiable as n grows. It now runs on a geometrically separated layout where exactly one field can dominate at any n, and a test pins both halves of that fact.

`contextual_joint_l838_experiment.py` is where L8.35 and L8.37 stop being addable. Conditioning each word's meaning on the episode and then solving the tuple is a sum of the two; what is not a sum is `B_c ⊆ Mⁿ`, where the **set of admissible assignments** is what the context selects. A world can then have, for two surfaces over `{a,b} × {x,y}`, `B_A = {(a,x),(b,y)}` against `B_B = {(a,y),(b,x)}` — every single-word candidate set identical across the contexts, and the sets different. What the context changes is only the **correspondence**, and a per-word account is blind to it by construction.

One consequence constrains what can be claimed, and it is worth stating because it is a real limit on the criterion rather than a convenience. **Identical unary marginals and `|B_c| = 1` are incompatible**: a singleton's marginals *are* its assignment, so two contexts with identical marginals and one solution each are the same context. The identity therefore holds at the level of the belief sets, and what has to be shown is that the difference between them is *usable*.

That is what the decisive family does, and the demonstration is the part that matters, since "the sets differ" on its own is bookkeeping. A per-word view of the evidence contains `フガ率: sim {runtime, success} / lab {runtime, success}` and `ホゲ尺: sim {energy, success} / lab {energy, success}` — identical everywhere, so there is no context effect for L8.35 to find. Then **one observation, the same one in both contexts**, arrives: `フガ率 = runtime_seconds`. In sim it makes `ホゲ尺` mean **success_rate**; in lab it makes it mean **energy_error**. With the labels erased the same observation leaves `AMBIGUOUS`.

`holdout_contextual_joint_l8381_experiment.py` reports `false_joint_resolution_rate` **0.000**, `context_conditioned_joint_accuracy` 1.000, `effect_accuracy` 1.000, `relational_only_gain` **1**, with `marginal_identity_verified` and `erasure_breaks_only_relational` both true — the erasure ablation breaks the relational family and leaves every other one untouched, which is L8.35's ablation lifted from one word to the tuple. The controls are what make that mean something: `INDEPENDENT_POLYSEMY` has marginals that *do* differ, so a per-word account explains it and the layer must not claim credit; `CONTEXT_IRRELEVANT` has identical sets and is reported as no effect rather than as a context dependence; `SYMMETRIC_WITHIN_CONTEXT` stays ambiguous under the probe; `CONTRADICTION` reports an empty context rather than filling it in. The gate is unchanged throughout — `|B_c| = 1` executes, `0` contradicts, `≥2` abstains — which is the same claim L8.37 made about n, now made about contexts.

`cost_aware_joint_l839_experiment.py` asks about that correspondence, and splits the question space three ways: **unary** (「sim の場面で フガ率 は runtime_seconds のことですか？」), **relation** (「sim の場面で フガ率 は ホゲ尺 より大きいですか？」) and **context/structure** (「この対応は sim と lab で同じですか？」). No kind is given priority. A question is scored by what it leaves standing over the possible worlds `W = { w : C → Mⁿ | w(c) ∈ B_c }` and chosen by L8.36's rule — literally the same code, which gained only an `ask_pool` argument: solvability is a **veto**, then expected remaining ambiguity, then Pareto-minimal cost with the cost still a vector. What separates the kinds is not price but what they are able to *name*: a unary question has to name a meaning, and the project has modelled since L8.29 that some fields cannot be named — a word is coined precisely when the person has no name for the quantity. A relation question names only the two surfaces the person already used; a context question names only the episodes.

`holdout_joint_dialogue_l8391_experiment.py` reports `false_joint_resolution_rate` **0.000**, `joint_dialogue_accuracy` 1.000, `unnecessary_question_rate` 0.000, and in the decisive `COUPLING_ONLY` world **`Q_unary informative = 0` against `Q_relation informative = 2`**. `integration_benchmark_l840_experiment.py` runs L8.13–L8.39 as one episode in thirteen stages — new episode → unknown words → joint ambiguity → the context turns out to matter → a question → 「分からない」 → another question → the meaning is acquired → the original goal resumes and executes → contradicting evidence → `DISPUTED` → the split is read as polysemy → each episode runs again with its own sense — auditing the same three things **after every stage**: `wrong_answer`, `false_acquisition` and `stale_episode_leak`. `contextual_nway_l841_experiment.py` puts L8.37 and L8.38 in the same world rather than side by side. `holdout_contextual_nway_l8411_experiment.py` builds `CONTEXT_GLOBAL_ONLY` from what it denies, and measures each denial instead of asserting it. Drop the non-decomposable n-ary constraint and **every episode goes AMBIGUOUS** (the binary chain cannot say which surface dominates); drop the episode labels and the union of two different unique answers is **AMBIGUOUS**; keep both and each episode is **RESOLVED**; add one observation against an episode's own answer and that episode is **CONTRADICTION** while the other stays resolved. Two disclosures go with it. First, `SYMMETRIC` at n=3 enters **more nodes than the product has points** (30 against 27), because a search node is a *partial* assignment and there is nothing to propagate: propagation buys nothing where there is no constraint to propagate, so the headline family's ratio is a statement about that world rather than about the solver. Second, this family found a latent crash in L8.37's propagator — a unary observation can empty a domain mid-sweep and the `DOMINATES_SUM` filter reads its partners' extremes, which an empty partner has none of. L8.37.1 never reached it because its contradiction arrives through `ALL_DIFFERENT`, whose filter tolerates an empty domain. `propagate` now bails the moment a domain empties, and the test pins the direction.

`question_accessibility_l842_experiment.py` removes the assumption every layer since L8.32 has carried: that a question the planner can think of is a question it can ask. Some are **not in the action space at all** — the person cannot recall an episode they have not opened, and cannot compare two episodes one of which they cannot refer to. The design decision is the whole layer: `askable` does **not** join the cost vector. `Q_available(s) = { q ∈ Q : askable(q, c, s) = 1 }` is formed first, and then L8.36's chooser runs over it **unchanged**, through the same `ask_pool` seam L8.39 opened. Modelling "cannot ask" as "very expensive" would let a large enough tie-break, or a world with no alternative, talk the planner into asking it anyway; there is no penalty value here to be outweighed. It is L8.36's own distinction seen from the other side — capability was a veto, cost was a comparison, and accessibility belongs with the veto.

The consequence is a state the earlier layers could not express. `IMPOSSIBLE` used to mean "nothing would help"; with accessibility it splits into **`IMPOSSIBLE`** (no question is informative at any level of access — abandoning the goal is correct) and **`BLOCKED`** (an informative question exists and is out of reach right now — reporting it as `IMPOSSIBLE` would permanently abandon a task that one further action would finish). Both are made falsifiable rather than asserted: every `BLOCKED` claim is checked by re-running the *same* planner with full access and watching it finish, and every `IMPOSSIBLE` claim by checking that full access still does not.

`holdout_accessibility_l8421_experiment.py` runs one world at four levels of access. With everything open a single three-way question finishes it (**1 turn**); with the `lab` episode's details closed that question is not in the action space and two reachable context questions finish it (**2 turns**, detour 1); with only `lab` referable there are **15 informative questions and 0 reachable**, so nothing is asked and the state is `BLOCKED`; and with unnameable twins no relation distinguishes there are **0 informative questions at any access level**, so the state is `IMPOSSIBLE`. `false_joint_resolution_rate` **0.000**, `unaskable_question_rate` **0.000** (audited against `askable` read off the question text, independently of the pool that produced it), `blocked_prediction_accuracy` and `impossible_prediction_accuracy` both **1.000**.

`HIGH_COST_BUT_ASKABLE` is the control that keeps the two ideas apart, and it is measured rather than argued. With the episodes out of reach the planner asks a question costing `(1, 2, needs_context=True)` while an *unavailable* one costs `(1, 2, False)` — strictly cheaper, and strictly dominating under L8.36's Pareto rule; handed the same world fully reachable, the same planner picks that cheaper `CONTEXT` question instead. A cost vector cannot express that, which is why `askable` is not in it. `ACCESS_UNLOCKS` then runs the state change — `BLOCKED`, the person opens the episode, one question, resolved — while the genuinely out-of-reach world stays `IMPOSSIBLE` with every episode open.

`semantic_service.py` は L8.27–L8.42 をベンチマークから出して製品の裏側に置く継ぎ目である。持つものは3つだけ——解釈状態を所有する1つのセッション、デスクトップ版と Web UI の**両方が呼ぶ**コマンド面、そして inspector パネルが描画する JSON スナップショット。合成は意図的に薄い。決めることはすべて既存の層が決めているからで、`SemanticSession` は `Dialogue`（L8.27–L8.33）を保持して**何が起きたかを報告するだけ**であり、質問の生成も回答の束縛も語義の獲得も改訂もここでは再実装していない。L8.31 が「そもそも学習可能か」を、L8.35 が episode ごとの語義を、L8.36 が L8.35 が開いたままにした**モデルについての質問**を、L8.42 が「その質問は今そもそも訊けるのか」を、それぞれ担当する。

### 検証済みの質問形式を、編集できるテンプレートとして

### 対話を Python 風の呼び出しで書く

「はい」と打つのは1回の返答なら十分で、列には全く向かない。episode を開いて、訊いて、答えて、モデルを名指して、実行し直す——この5手は**順序こそが中身**なのに、散文にはそれを書き留める手段も、残す手段も、人に渡す手段もない。そこで `dialogue_script.py` が同じ行為にコードの形を与える。

```python
open_episode("lab")
ask("64x64のケースで処理時間ではなくフガ率をならして")
no()
rerun()
```

安全にするための判断は3つで、**どれもこのプロジェクト自身の規則が入力層に再登場したもの**である。①**何も評価しない**——`ast` で構文解析して固定の表と照合するだけで、`eval` も `exec` も使わない。式・属性・import・内包表記のどれからも外へ手が届かず、表にない形は**試す前に名前で拒否する**（L8.27 が修理して初めて手に入れた fail-closed の既定と同じ）。②**1行でも読めなければ1行も実行しない**——4行目の打ち間違いは1〜3行目も起きなかったことにする。これは L8.18 の実行ゲート（evoked ∧ ¬resolved ⇒ 実行しない）を演算の引数ではなく**入力言語に**当てたもので、半分しか解釈できていないスクリプトは半分実行されない。③**呼び出しはセッション自身の行為だけ**——算術も変数も制御構文も無い。目的はエージェントをプログラムすることではなく、**会話をそのまま書き留めること**だから、層が露出していないものには呼び出しが無い。

入口は3つ。```` ```python ```` ブロック、`/py <code>`、そして**平文に混ぜても効く**——メッセージが表の呼び出しだけに**完全に**構文解析できたときだけスクリプトとして扱うので、散文も `/inspect` も `64x64(の平均)を出して` も素通りする（`looks_like_script` の保守的な判定）。API は `POST /api/semantic/script`。UI は inspector の `SCRIPT` セクションに等幅のエディタと実行結果（行・呼び出し・状態・結果）を出し、拒否は拒否として赤く表示する。

### 算術と、場と式を宣言する言語

`1+1=?` と打ったら `2` と答える。素直にやるなら `eval` で、素直なやり方は間違っている——入力はテキストボックスから来るので、`__import__` に手が届く評価器は電卓の皮をかぶったリモートシェルである。`math_expression.py` は `ast` で構文解析し、ノード型・演算子・関数・定数の閉じた表と照合して歩くだけにした。表にない形は**試す前に名前で拒否**する。`^` は排他的論理和ではなく冪として読む（Python では xor で、Python ではそれが正しい。ここで囲んでいる言語は数学で、`2^10` と書いて 1000₂ xor 1010₂ のつもりの人はいない）——演算子の黙った読み替えこそ黙っていてはいけないので、明記して変換している。`=?` で終わるか、算術だけでできた行のときだけ答えるので、`これは1+1みたいな話です` は素通りする。

`physics_script.py` は「プログラムっぽい文章」の方である。

```physics
vector: B = (0, 0, Bz)
lorentz: F exists
calc(m d^2 x / dt^2 = lorentz(B))
draw(x)
```

**この言語で面白いのは ODE を積分するところではなく、`Bz` をどう扱うかである。** `Bz` は書かれていて値が与えられていない——つまり対話層の 「フガ率」 と**同じ形の問題**、人が使った記号でシステムがその意味を持っていないもの。だから対話層が辿り着いた規則がそのまま効く: **未解決の記号の上で実行しない**。スクリプトは止まり、足りないものを挙げ、それを束縛する行を提示する。`Bz = 1` と推測すれば、**誰も書いていない世界の絵を自信たっぷりに描く**ことになる。

誰も打っていない値が出てくる唯一の場所については、線を明示した。**人が持ち込んだ記号には既定値が無い**（`Bz` と、人が自分の式に書いた質量）。**システムが持ち込んだ記号にはある**（電荷 `q` は人の文ではなくローレンツ力の側の量、初期位置・初速度・時間範囲は述べられた物理ではなく絵の描き方）。後者は**すべて出力に「こちらで補った値」として理由つきで並ぶ**。

残りは既存の規則のままである。何も評価しない。1行でも読めなければ1行も実行しない（L8.18 の実行ゲート）。未知のキーワードは推測せず、**最も近い既知のものを添えて**拒否する——`lorentz: F exitst` は「`exists` のことですか？」、`lotentz(B)` は「`lorentz` のことですか？」と返す。限界も発見ではなく明記した: 場は一様（成分は数値に評価されること）、非相対論的、固定刻み RK4。**そして解析解と比べている**——`B=(0,0,B)` で電場が無ければ運動はらせんで厳密解が分かるので、`analytic_error` として最大ずれを毎回出す（実測 1.67e-09、テストは上限で固定）。ソルバを自分自身とだけ比べても検証にはならない。

### 関係の推論と、記号が曖昧なときの答え方

`(A in B) and (B in A) ならば？` には答えが**2つ**ある。`in` を `⊆` と読めば反対称律（外延性）から **A = B**、`∈` と読めば正則性公理から **矛盾**——ZF に互いを要素として含む2つの集合は存在しない。

つまり `in` は、**人が使った記号でシステムがその意味を持っていないもの**——「フガ率」 と、物理言語の `Bz` と、まったく同じ形の問題である。だから対話層が辿り着いた規則がそのまま効く: **曖昧さが無かったことにして答えない。** `logic_reasoner.py` は読みを選ばず、**すべての読みを同時に運ぶ**。それぞれの帰結を導き、どの読みかをラベルにし、ひとつに決めたい人には決め方を示す。`in := subset` と打てば以後そのセッションでは固定される——**語について質問に答えて語彙が定まるのと同じ手**で、だから読みは reasoner ではなく**セッションの解釈状態**の側に置いてある。

`⊂` も別の理由で曖昧で、同じ扱いをする。ある教科書は `⊆` の意味で書き、別の教科書は `⊊` の意味で書く。黙って片方を選ぶ推論器は、読者の半分に嘘をついている。

### 定理発見システムの統合

`theorem_discovery_system/` はこのパッケージの隣にある研究用スキャフォールドで、Lean から抽出した 42 件のコーパス、代数法則を立てて有限モデルで篩う発見核、そして自前のテスト一式を持っている。`theorem_service.py` はそれをチャット・HTTP API・パネルから検索・実行・検証できるようにする継ぎ目である。

**import せず、サブプロセスとして動かす。** 理由は3つとも「研究用スキャフォールドをエージェントのプロセスに入れない」ことに尽きる。①モジュール名が `corpus` `codec` `compressor` `diagram` のような素の名前で、あのディレクトリを `sys.path` に載せるとエージェントやライブラリの import を横取りしうる。②データパスがバンドル根からの相対で、README 自身が「このフォルダの中から実行せよ」と言っている——`cwd` を設定したサブプロセスはまさにそれである。③バンドルの記録には**停止しない実験**があり、bridge のプロセス内でハングすればエージェントごと巻き込む。サブプロセスならタイムアウトが効く。

**数え方を分けたまま出す。** 発見核自身の docstring が言っている——`asserted` は**有限モデル篩を通った本数であって、証明された本数ではない**。証明は `valid` で、それが動くのは Lean が実際に呼ばれたときだけである。だからこのモジュールは発見を定理として報告しない: `asserted` と `valid` を並べて出し、`lean_calls` が 0 のときは**言葉で「1 回も呼ばれていません」と書く**。これは L8.22 の規則の別衣装（篩に提案権、証明器に決定権）で、two を one にまとめることこそこのプロジェクトが測り続けている confidently wrong である。実測では 12 周期で `asserted` 2 / `valid` 0 / `lean_calls` 0、つまり**証明されたものは無い**。証明義務は `/theorem obligations` が Lean ファイルとして出す。

**統合して移植バグが1件出た。** バンドルの README は「`theorem_discovery_system/` を別プロジェクトにコピーして、このフォルダの中から実行せよ」と書いているが、`python/test_discovery_core.py` の `CORPUS` が `parents[2]`——つまり**バンドルの外**、元のスキャフォールドの位置——を指していた。フォルダが動いた時点でそのファイルは無いので、5 件のテストが落ちる。バンドル自身が同じ内容の `theorems.json` を `parents[1]` に持っているので、そこを指すように1行直した（理由をコメントに残してある）。これで `51 passed`。`qg_verification.py` と `test_qg_verification.py` にも `parents[2] / "physics_analysis_model"` という同種の残骸があるが、`physics_model.py` は `python/` の中にあって実害が無いので**報告だけして触っていない**。

表に出る口は4つ: チャットの `/theorem` `/theorem search <語>` `/theorem run [周期]` `/theorem obligations` `/theorem verify`、スクリプト言語の `theorem_search("assoc")` と `theorem_run(12)`、API の `GET /api/theorem/status` と `POST /api/theorem/{search,run,obligations,verify}`、そしてパネルの `THEOREMS` セクション。出力は長い markdown なのでパネルには出さず**会話に流す**——パネルに残るのは「何であるか」と、頼める数少ないことだけである。`/theorem verify` はバンドル自身のテストをエージェント経由で走らせる（51 passed）ので、移植の正しさもここで確かめられる。

**柵の内側**: 規則はこれで全部で、探索も算術も集合構成も無い。前提は名前のついた集合の上の連言で、導出は不動点まで前向きに閉じるだけ。選言的な前提・量化子・否定された包含・具体的な集合は、近似せず**名前を挙げて拒否**する。そして**成り立たないことも報告する**——導けるものだけを印字する推論器は残りを読者に補わせることになり、ここでの取り違えはたいてい「導けない方」にある（`∈` は推移的でない、`⊆` からは `∈` は出ない）。導かれた事実には**使った規則と前提**が並ぶので、結論だけを信じる必要はない。

入口は UI の同じ `SCRIPT` 欄で、どちらの言語かは**モード切替ではなく構文解析の結果**で決まる。値の無い記号があると、パネルはそれをチップで並べて「推測しないので実行していません」と言う。図は PNG の data URI として会話に入る。

テンプレートとも接続した。各テンプレートは散文形に加えて**同じスロットを持つ呼び出し形**を持ち、picker に「文として／コードとして」の切り替えが付く。そして契約検証が**両形式の等価性を毎回測る**: `yes()` と 「はい」 は同じ手の2つの書き方なので、着地する状態が食い違ったらコードの側は「検証済みの対話を書き留める手段」ではなく**別の、検証されていない対話**になってしまう。実測では `expect` を持つ9件すべてで `decision` と `commits` が一致し、`ask(...)\nimport os` は**1行も実行せずに**拒否されることも HTTP 越しに確認した（契約検証 50/51、唯一の NG は「bundle がソースより古い」）。

UI 側は inspector の `VERIFIED TEMPLATES`。形式を選ぶと**スロットが個別の入力欄**（`条件` `除外する指標` `未知語`、訂正先の指標や episode 名は選択肢つき）になり、その下の**テキストエリアに展開結果が入って自由に編集できる**。ボタンは3つ——「送信」は種別ごとの経路へ（REQUEST は `/api/semantic/ask`、ANSWER は `/api/semantic/answer`、COMMAND は通常のチャット）、「入力欄へ」は composer に流し込んでさらに書き換えさせ、「スロットから戻す」は編集を捨ててスロットから作り直す。**テンプレートを固定ボタンにしなかったのは、変えられない雛形はボタンでしかないから**で、検証されているのは*形*であって語そのものではない。送った文は本人の発話として transcript にも入る（返答だけが現れると、エージェントが独り言を言っているように読める）。

検証を通すと `/api/semantic/rerun` が**API にあって UI から呼ばれていない**ことも分かったので、`last_request` をセッションに持たせて panel に「各 episode で実行し直す」を足した。これで UI が呼ぶ endpoint と bridge が出す endpoint が一致する。

付随して `coding_agent_app.py` の tkinter import を任意にした。デスクトップ窓はツールキットを要るが、`LocalWorkspaceAgent` と HTTP bridge は要らない。これで headless でも bridge と API がそのまま import でき、**tkinter 不在で収集できなかったテストファイル 11 個（+87 テスト）が動くようになった**。残る収集エラー 9 件は `datetime.UTC`（Python 3.11 以降）を Python 3.10 で読んでいるもので、tkinter とは別の既知の環境差である。

Ablation reports what each sensor is worth as `ΔC_s = C_all \ C_-s`. Structure contributes two queries nothing else can reach. The whole-sentence sensor contributes **nothing** on this set -- every query it carries is also carried by a span -- which is reported as measured rather than smoothed over. The span figure is inflated and labelled as such: structure locates candidates through the span sensor's boundaries, using their positions but never their labels, so removing spans also removes structure's ability to attach to anything.
